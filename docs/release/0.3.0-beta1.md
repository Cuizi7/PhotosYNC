# PhotosYNC 0.3.0 beta1

版本：0.3.0 beta1（build 18）。最低 macOS 13，Universal arm64/x86_64。本次为本地 ad-hoc 签名 App／DMG；确切源码、发布验收和产物身份由随包 `PhotosYNC.provenance`、`validation/` 与 `SHA256SUMS` 绑定。

## 本版行为

- **完整 Live Photo。** 默认将精确配对的 HEIC/JPEG 与 MOV 原资源作为一个原生 Live Photo 保存，保留静态画面、动态和原有声音；不转码，不新增设置。来源只有一半时先保存，发现另一半后补齐，图库既有单项也走同一流程。
- **目录完成后放行。** 每个文件夹完成直属枚举和有界身份识别后才开始导入；其他已完成文件夹可以继续，避免同目录两半按枚举顺序误入单文件提交。
- **首次历史识别只完成一次。** 全库身份识别分批执行并持久保存进度；完成后重启或常规升级不重跑全库。未知项独立重试，初次盘点和自动待核实重试不联网下载原件；精确定位的补齐和验证按预算读取资源。
- **验证后替代旧单项。** 新建或复用完整目标，确认准确原资源及其余受保护信息已保留后，再删除被替代的精确单项。按用户决定不保护标题：标题未知或不一致不会阻止清理，旧标题可能丢失。日期/位置、收藏/隐藏、说明、评分、关键字、相册、编辑和额外资源仍按既有保留规则核实。
- **恢复和资源约束。** 创建及清理共用一个实际 PhotoKit 提交槽位，未知结果保持阻断；成功历史和用户删除证据保留。Photos 原资源临时存储沿用 512 MiB 总预算及 128 MiB 磁盘保留，物理读取结束前不提前释放；来源始终只读。

删除仅针对精确确认、验证通过的旧独立组成项，包含非 PhotosYNC 导入的项目；不删除完整 Live Photo，不清空“最近删除”。资源、版本、受保护信息或图库连续性不明时，可以保留旧项并延迟处理。

## 升级与数据库

事务迁移至 **schema v11**，保留源配置、成功历史、已有分析成果及未确认提交。0.2.9 及更早的 App 无法直接读取升级后的数据库；不要通过恢复旧数据库抹掉后续成功历史来降级。

打包不安装或启动 App，不备份、迁移或清理生产同步数据库。本功能首次正常运行才执行对应的历史识别与同步逻辑。先前开发版已持久化为无限等待的补齐操作不由本版强制重置；资源 revision 检查仍有效。

## 验证范围

开发行为快照 `332d002` 通过过完整 full 四档；标题规则快照 `c300952` 最终通过 849 项 XCTest（2 项明确跳过、0 失败）、102 项工具测试、最大混合规模与两种续体竞态。首轮有效性能超限、定向复测及完整重跑记录均保留，未修改阈值，具体尾延迟原因尚未确定。这些是开发记录，不能替代本发行归档的新验收。

在用户批准的本机限定系统测试中，三个自制 QA 项（照片、视频、完整 Live Photo）创建成功，原始字节和音轨核验通过，随后按精确 ID 清理；最近删除保留。原生查看组件对同字节本地原件完成后台静音播放和音视频解码。私人导出素材和 QA 工具均在忽略目录，不进入源码归档、发行包或 GitHub。

以上系统证据不代表 Photos.app 手动手势、外放听感、真实 iCloud 多设备、macOS 13/14 或 Intel 实机已通过新一轮验收。公开 API 缺少稳定物理图库 ID，历史工作恢复依赖正向资产证据；全部锚点消失等不确定情况保持等待。

## 本地发布

从 squash 合并后的 `main` 确切提交执行：

```sh
scripts/package-release.sh --scale-profile full
```

本版涉及索引、持久化和资源行为，明确选择 full：10 万、15 万、20 万表示及 20 万表示＋10 万成功历史四档。完整无过滤 XCTest、Tools、模型/资源门槛、两种受控续体 GREEN／预期 RED、正常 Universal Release 构建、版本/channel/build、逐层签名、图标、DMG 和校验值检查均保留。

目标目录 `outputs/releases/0.3.0-beta1/`，已存在时拒绝覆盖。交付包含 `PhotosYNC.app`、`PhotosYNC-0.3.0-beta1.dmg`、发行说明、changelog、provenance、validation 和校验值。实际成功与否以该目录的本次证据为准。

未做 Developer ID 签名或 Apple 公证；本次不安装、不启动正常生产 App，也不推送或公开远端发布。
