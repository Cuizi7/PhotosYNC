# PhotosYNC 来源恢复改进方案（待批准，不包含本次实现）

## 问题与目标

已实测：WebDAV或手工SMB挂载卸载后可能留下可读空目录。当前只检查路径存在/可枚举，因此把空挂载点误报恢复。目标是确认“原来源身份恢复”，而非仅确认路径可读。保持所有目录同一逻辑，不增加local/network产品类型，不自动挂载，不保存网络凭据，不写源标记，不做删除同步。

## 推荐规则

每个来源保存身份基准；扫描开始、结束及新提交前做有界重新观察。明确身份冲突或身份不完整时停止该来源的新提交，已提交结果继续记账。仅完整成功扫描且身份确认后清除等待/通知恢复；已有单文件错误仍保持聚合状态。保留5/15/30/60秒退避，禁止绕过物理I/O上限。

身份候选：可用的持久卷UUID、根目录document identifier、规范化且去凭据的挂载来源与文件系统类型。实现前须用目标NAS做采样实验，确认同一共享卸载/重挂/服务器重启后的字段稳定性；不能假定SMB/WebDAV均提供稳定UUID或目录ID。nil不是相等证据，暂时缺失不能覆盖已保存基准。不得把volumeIdentifier/f_fsid作为跨重启持久身份，不把目录mtime/generation或媒体内容作为身份。

比较分为匹配、明确冲突、证据不足。卷/挂载来源一致本身不足以证明同卷的根目录没有替换。挂载来源必须解析去除userinfo等敏感字段；解析失败宁可不持久化，不能原样记录statfs字符串。身份UUID/目录ID的持久性仅在其所在文件系统实际支持时成立。URL资源缓存不能代替本轮新读取。

- 匹配：允许枚举；正常空来源也允许完成。
- 冲突：等待并说明“该路径目前不是原来源”，禁止把新身份覆盖成基准。
- 证据不足：首次登记提示无法自动确认身份；离线恢复/升级无基准时要求用户验证，不能靠非空目录自动证明来源正确。
- 扫描中断开/替换：本轮不报成功，新提交前的核对再次拒绝变化；不宣称能原子消除所有路径替换竞争。

## 持久化与升级

schema v3→v4事务新增source_identity一对一表，含version、可选volume_uuid/root_document_id/normalized_mount_origin/filesystem_type和验证时间；保留全部旧source/file_record成功历史。Schema.sql和迁移代码同步。旧来源没有基准时不能自动采纳当下空挂载点；建议首次升级要求“验证来源”。相同来源的重新验证保留UUID和历史；若确认为另一共享，停用旧来源并另建UUID，不静默复用相对路径历史。

需要批准的取舍：旧来源首次升级要求人工验证；无法提供足够稳定身份的文件系统，在断开恢复后可能需要人工确认。这是保守方案的可用性代价。

## 实施顺序与验收

1. 在真实目标NAS只读采样身份，验证重挂稳定性，确定支持/降级规则后再实现。
2. 纯比较策略与fixture测试；v3→v4事务迁移/失败回滚测试。
3. 接入统一目录观察、扫描结束与提交前核对；多来源独立等待，继续用现有调度器。
4. 原生设置增加身份不足/冲突提示与明确验证动作；通知只在完整恢复后发出。
5. 真实WebDAV空挂载点、SMB手工空挂载点、系统管理挂载点消失、同共享重挂、不同共享替换、同卷根目录替换、合法空目录、重启后恢复、慢读/挂起I/O、扫描中断开逐项验收。断开不新增、恢复不重复、源不变、既有历史不清空。

估计为中等范围改动，含持久化/并发提交约束，不应作为小修混入此次发布。工作量需在真实NAS身份采样后估算，不能用mock通过替代协议实测。

## 官方依据

- Apple URLResourceValues.volumeUUIDString：持久UUID可能不可用。
- Apple URLResourceValues.volumeIdentifier：不跨系统重启持久。
- Apple URLResourceValues.volumeMountFromLocation：文件系统设备来源；不作为唯一身份。
- Apple URLResourceValues：并非所有文件系统提供每种属性，缺失可返回nil。

文档地址分别为developer.apple.com/documentation/foundation/urlresourcevalues下的volumeuuidstring、volumeidentifier、volumemountfromlocation及类型首页。资料核对2026-09-15。网络实測现有证据见Design/Validation.md。
