# PhotosYNC 0.2.7

版本：0.2.7 stable（build 15）。最低 macOS 13，arm64/x86_64 Universal。确切发行源码、验证结果及产物身份由本次 `PhotosYNC.provenance` 与 `SHA256SUMS` 绑定。

## 本版改进

- **相同成功日期直接沿用分析。** 在同设备持久资产身份域、相同资产 ID、original/current 表示和分析契约下，相同且有效的成功修改日期直接复用已有向量，不读图、不准备模型输入、不计算输入摘要或推理。资源描述、revision 或内容通知不额外推翻这一日期匹配。
- **日期变化只处理该项。** 读取对应表示并准备实际模型输入后，与可靠绑定成功向量的兼容摘要比较；相同则复用向量并确认新成功日期，不同才推理该项。失败保留原成功日期、向量、摘要和契约，按已有退避逐项重试，不把新观察日期提前记为已成功处理。
- **历史恢复保留成果。** token 过期、详情不可用或 checkpoint 损坏时，保留同设备资产身份域和成功分析，退化为元数据对账；临时历史错误保留缓存并退避。可能需要枚举整库资产元数据，但不会因此清空成果或全量重建图像分析。没有证据表明应用版本升级必然导致 token 失效。
- **修复跨轮返回与取消窗口。** 完整清单确认移除后，相同 ID/有效成功日期/分析契约重新出现，完成成员关系对账后可复用保留向量。预读取快照等待期间发生取消时，不再继续接纳新的读取或预测工作；已持有工作的物理清理约束保留。

任何恢复都不走全量清空重建。新资产、无有效日期、缺少兼容成功成果或分析语义契约变化的项目，仍须逐项验证或计算。保留的旧向量不会绕过当前性与清单发布屏障；不完整、无权限或中断的清单不能作为删除证据。

## 升级与数据库

schema 升为 **v10**，通过事务保存当前观察日期、成功分析日期、成功向量版本以及成功输入摘要与向量的配对关系。支持从 v3–v9 升级，保留已有向量、任务及成功导入历史，不批量作废 ready、不清理生产数据。v9 没有原始成功日期，迁移不会从 revision hash 反推或伪造证据；首次元数据对账仅在能证明匹配时补齐该项事实，其他项目逐项核查。

schema v9 或更早的应用会拒绝升级后的数据库，不能直接降级。升级安装前应正常退出应用并备份完整 Application Support 目录，包括 WAL/SHM；发行构建不会代为安装、启动、备份或迁移生产数据库。不要在新导入后用旧数据库回滚而丢失成功历史。

模型、0.98 阈值、现有输入算法、来源只读、Photos 仅新增以及成功导入和 unknown 提交保护沿用既有规则。完整增量契约见 [Photos ID/date 增量分析](https://github.com/Cuizi7/PhotosYNC/blob/v0.2.7/docs/specs/2026-10-17-photos-incremental-recovery.md)。

开发最终快照和独立 scoped recheck 已通过。正式发行仍从最终干净 main 提交归档执行完整无过滤 XCTest、Tools、full 四档规模、两条受控续体 GREEN/预期 RED、模型/资源门槛，以及正常 Universal Release 构建、签名和 DMG/校验值检查。实际成绩以本次随包证据为准。
