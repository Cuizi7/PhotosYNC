# PhotosYNC 0.2.2

发行准备日期：2026-10-16（Asia/Shanghai）。目标配置：0.2.2 stable（build 10），最低 macOS 13，arm64/x86_64 Universal。**当前尚未发布：冻结 `125ada6` 已通过完整自动验收，集成静态代码/规格/架构评审已批准；评审者补核最终验证及真实屏幕浮层/材质验收仍待完成，合并及发布保持阻断。** 实际源码提交、完成结果与校验值由本次发行的 `PhotosYNC.provenance` 和验证记录绑定，不预填未知值。

## 本版两项修复

- **来源问题详情更完整。** 菜单和设置统一显示“发现 N 项问题”，可通过 hover、点击或键盘打开详情，查看当前各项问题的完整路径、原因、已知失败阶段和系统诊断。同一问题重试不重复计数；长路径和错误可换行、复制，长内容可滚动查看。无法确认根因时明确保留不确定性。
- **图库分析与同步详情一致。** 详情显示与主菜单一致的图库分析状态、资产进度和等待原因，并在打开期间持续更新。分析就绪后保留详情入口和已打开的浮层；图库资产、来源累计记录与本次扫描分别说明。

## 行为与升级边界

本版无新增数据库迁移，继续使用 schema v8；视频元数据失败保留实际读取阶段和原因，不扩展视频兼容性、不转码。照片判重、模型、0.98 阈值、Photos 取图、提交/恢复/调度决策、权限及依赖保持既有规则。来源文件严格只读，Photos 仅新增；成功历史和未知提交保护继续有效，不删除或覆盖既有资产。

从 0.2.0/0.2.1 升级无需新迁移。从 0.1.0 升级仍遵循既有 v3–v8 迁移和指纹重建规则。首次启动前，正常退出 PhotosYNC，并备份完整 `~/Library/Application Support/PhotoSync/`，包含 SQLite WAL/SHM 等配套文件。旧应用不能直接打开升级后的库，恢复旧库可能丢失后续导入成功证据并造成重复新增；完整既有模型、资源、iCloud、升级和降级边界见 [0.2.1 发行说明](0.2.1.md)。

## 验证与分发限制

完整自动验收绑定 `125ada636248249fe74bc87299f598a0eac77950`；本次仅更新文档事实，未对较晚的文档提交重跑测试。静态评审无 P0–P2，已接受的低严重性诊断边界及最终验证补核状态详见记录。自动通过和静态内容审阅不能替代真实屏幕浮层/材质验收。具体测试快照、采集结果、恢复边界和后续关卡见[本轮验证记录](2026-10-15-diagnostics-and-analysis-validation.md)。本轮未新增真实 Photos 或生产数据实测；macOS 13 与 Intel 实机按用户要求不执行，Universal 构建不能替代实机运行。物理 hover、完整键盘/焦点、系统 MenuBarExtra 和 VoiceOver 仍有未验证边界。

通过合并与发布门槛后，从确切干净 main 提交执行 `scripts/package-release.sh`，在归档内重新完整验收并核验 Universal app/Core、版本、资源、签名、DMG 和校验值。目标目录 `outputs/releases/0.2.2/` 不得覆盖已有路径，旧包和证据保留。当前尚未创建本轮发行包或 tag/release；实际交付身份和结果以本次 provenance、validation 与 SHA256SUMS 为准。

分发沿用 ad-hoc 签名，未进行 Developer ID 签名、公证、stapling 或 Gatekeeper 验收。换新构建后系统可能要求重新授权；本次发行准备未安装或启动生产 App，也未更改系统权限。
