# PhotosYNC 0.2.2

发行准备日期：2026-10-16（Asia/Shanghai）。目标配置：0.2.2 stable（build 10），最低 macOS 13，arm64/x86_64 Universal。**当前尚未发布：最终完整自动验收、集成深度评审和真实屏幕浮层/材质验收待完成，合并及发布保持阻断。** 实际发行日期、main/tag 提交与产物校验值只能在完成后记录；版本配置不代表包已生成。

## 本版两项修复

- **来源问题详情。** 菜单和设置的来源行只用“发现 N 项问题”汇总当前未解决的诊断身份；同一问题重试不重复计数。原生详情按目录与连接、读取与解析、导入与提交分组，保留完整路径、准确人话、已知阶段和可取得的嵌套系统 domain/code/description。逐目录恢复后，首条原因来自仍未解决的成员；既有来源恢复标记仍须完整遍历证据才清除，不能将单个目录恢复当作整个来源恢复。只在完整且未延迟/中断的遍历证明旧扫描问题对应条目消失时清除该内存诊断，不清提交问题或成功历史。
- **图库分析与同步详情一致。** 详情使用与主菜单同一快照的分析状态、资产进度和等待/异常原因；分析期间更新，ready 后只移除分析组并保留同一个入口与打开的浮层。图库资产、启用来源的累计记录和本次扫描分别说明，representation 数不混入资产进度。

来源问题摘要可 hover、点击或键盘打开原生详情；长路径和错误换行并可复制，长内容内部滚动。视频四个既有必需元数据读取步骤失败时保留实际阶段和系统原因；无更明确证据时说明原因尚不能确定，不猜测损坏、缺解码器或格式不支持。失败仍报错，健康兄弟继续；这不是视频兼容性扩展。

## 沿用的行为与升级边界

本版保持 schema v8，无新增数据库迁移；不改变照片判重、0.98 阈值、SSCD 模型与资源、Photos 原始版/当前编辑版取图、提交/恢复/调度决策、系统权限、bundle identity 或最低系统版本，不新增运行时依赖。来源文件严格只读，Photos 仅按既有语义新增；成功历史和未知提交保护继续有效。不转码、不配对 Live Photo、不自动挂载来源、不删除或覆盖 Photos 资产。

从 0.2.0/0.2.1 升级仍使用 schema v8。从 0.1.0 的旧库升级继续执行既有 v3–v8 事务迁移和指纹重建规则；本轮未新增或实测生产迁移。首次启动升级前，正常退出 PhotosYNC 并备份完整 `~/Library/Application Support/PhotoSync/`，包含 SQLite WAL/SHM 等配套文件。旧应用拒绝升级后的数据库，不承诺直接降级；恢复旧库可能丢失后续导入成功证据并造成重复新增。打包不启动应用、不备份或迁移生产数据。完整既有模型、资源、iCloud、升级和降级边界见 [0.2.1 发行说明](0.2.1.md)。
