# PhotosYNC 0.3.0 beta7

版本：0.3.0 beta7（build 24），最低 macOS 13，Universal arm64/x86_64。本地 ad-hoc 签名 App／DMG；实际源码、验证结果和校验值以随包 `PhotosYNC.provenance`、`validation/`、`SHA256SUMS` 为准。

## 本版变化

- 设置新增“图像处理内存峰值上限”，默认 **2 GiB**，可选 512 MiB、1、2、4、8 GiB。用于照片解码和视觉判重，按需占用；模型、图库和系统缓存仍有额外占用，不是整个应用的 RSS 上限。
- 提高额度会在旧图像任务和物理读取结束后，自动重试此前因解码超限而搁置的照片。同值重启不重复开放重试；降低额度保留正在执行任务的原额度。
- 等待旧图像释放不阻塞图库清点、来源扫描、恢复及 Live Photo 工作。首次升级从旧 512 MiB 默认值提高到 2 GiB 时，也会安排一次超限照片重试。
- 删除设置页顶部冗余的同步边界说明，保留授权提示、任务状态和内存用途说明。

模型和指纹身份、schema v11、成功历史、来源只读、Live Photo 精确配对和未知提交保护保持不变。Live Photo 编码资源仍使用独立的 512 MiB 预算。

## 验证与分发

开发与 UI 证据见 [验证记录](../validation/2026-10-23-image-memory-settings.md)。发布从 squash 合并后的确切 main 归档执行 `scripts/package-release.sh --scale-profile full`，包含完整 XCTest、Tools、四档规模、两组续体竞争，以及版本、Universal、图标、签名、DMG 和校验值门槛。只有随包新生成的通过证据确认发布成功。

原生设置页采用假数据、隔离模型真实渲染，涵盖默认/自选值、浅深色和多来源布局；不等同于实际系统窗口、键盘或 VoiceOver 验收。本轮没有新增真实 Photos、大图实际 RSS、macOS 13/14 或 Intel 实机验证。

交付目录 `outputs/releases/0.3.0-beta7/`，已有目录拒绝覆盖。不安装或重启生产应用，不执行远端发布、Developer ID 签名或公证。
