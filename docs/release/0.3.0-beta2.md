# PhotosYNC 0.3.0 beta2

版本：0.3.0 beta2（build 19），最低 macOS 13，Universal arm64/x86_64。本次为本地 ad-hoc 签名 App／DMG；确切源码和验收结果以随包 `PhotosYNC.provenance`、`validation/` 与 `SHA256SUMS` 为准。

## 本版修复

- 历史 Live Photo 分析允许按需获取 iCloud 原件；beta1 留下的未完成项逐项续跑，已完成的一次性全库识别、分析成果和成功导入历史保留。
- Live Photo 长读取独立推进，不阻塞视觉索引；请求期限为 600 秒，外层等待为 610 秒。取消或超时后，物理读取实际结束前继续保留占用。沿用 512 MiB 编码资源总预算和 128 MiB 磁盘余量。
- 临时读取失败自动重试；确定的单项超限、固定配对工作集超限或解析问题暂停自动尝试，可主动重新扫描，或在准确资源变化后重新分析。共享资源暂忙按短退避等待。
- 菜单、设置和详情统一显示“正在准备／正在同步／等待恢复／已暂停／需要处理／同步完成”。视觉索引与 Live Photo 配对分别展示进度，下载和保存作为内部步骤；hover 说明分析目的、可能的流量及恢复方式。
- 修复暂停发生在异步核对期间仍继续读取、正常配对提交被显示为未知结果，以及资源替换后配对无法恢复的边界情况。未知 Photos 写入仍阻止新提交；确定保留的旧单项不再让状态一直显示未完成。

继续沿用 beta1 的精确配对、原始资源和声音保留、验证后替代旧单项规则。来源始终只读；不清空“最近删除”，不保护旧标题。没有新增设置，schema 仍为 v11。

## 验收与边界

开发阶段以合成媒体、临时数据库和可控 PhotoKit fake 验证读取生命周期、重启续跑、暂停、变化和并发组合；状态展示补充原生离屏明暗界面验证。开发证据及状态契约见[验收记录](../validation/2026-10-21-cloud-livephoto-status-repair.md)。最终从 squash 合并后的 main 确切提交运行：

```sh
scripts/package-release.sh --scale-profile full
```

full 明确包含完整 XCTest、Tools、10 万／15 万／20 万表示与 20 万表示＋10 万成功历史四档、模型与资源检查、两种续体竞态，以及正常 Universal Release、版本、签名、图标、DMG 和校验值检查。通过状态及实际数量只以本发行归档的新证据为准。

本轮未启动生产 App、读写生产数据库或对真实 iCloud-only 资产执行新下载验证；fake 通过不代表真实云端下载已实测。没有重复 beta1 的限定图库写入测试，也不新增声称 macOS 13/14、Intel 实机或 Photos.app 手势验收。未做 Developer ID 签名或 Apple 公证。

独立目标目录：`outputs/releases/0.3.0-beta2/`，存在时拒绝覆盖；本次不安装或公开远端发布。
