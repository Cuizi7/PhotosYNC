# PhotosYNC 0.1.0 beta2

Build 2; macOS 13+, Universal arm64/x86_64. This release supersedes beta1 without overwriting its tag or artifacts.

## Changes

- ARW/XMP and other unsupported formats are ignored before media candidate inspection. They do not count as checked or skipped and no longer produce auxiliary non-media skip records.
- Enabled, nonremoved sources have a persistent summary: imported, genuinely skipped, pending, importing. Counts come from one database aggregate and survive scan resets/restarts. They describe registered records, not a live filesystem inventory; historical success protections remain intact.
- Separate current/latest scan progress uses “本次扫描”: checked candidates and newly imported assets, completion/interruption state and time. Already imported files count as inspected candidates without being claimed as new imports.
- Notification preference and system authorization are separate. Authorization recovery clears only the notification warning; notification restrictions do not present as a failed Photos sync. Read-only status refresh never requests authorization automatically.
- Photos submission recovery advice is shown only for actual unknown submissions, not notification or unrelated settings errors.

## Offline cleanup

`scripts/cleanup-non-candidate-records.py` is a separate maintenance tool. Its default is a read-only dry-run. Apply deletes only old non_media_skip records where classification and ARW/XMP filename suffix both match. It creates a consistent SQLite backup and verifies protected synchronization/history tables. It does not read photo contents, call Photos, or launch/restart the app.

Do not run apply against production while PhotosYNC is running. Stop the app for the maintenance window, use the real instance lock, and retain the backup. No production cleanup or installation is part of this development run. The approved production database snapshot is tested only through disposable copies.

## Distribution and limits

This is an ad-hoc signed local beta, not Developer ID signed or notarized. Build with `scripts/package-release.sh` from a committed checkout; results are isolated in `outputs/releases/0.1.0-beta2/` with commit provenance and checksum. Automatic database backup, RAW import, deletion/overwrite sync, exact-content deduplication and mount identity recovery remain outside this patch.

Validation details are recorded in the delivery report. Tests use isolated files and injected gateways; production sources, library, configuration, and running app are not changed. Full manual production GUI/permission acceptance requires a separate approved deployment.
