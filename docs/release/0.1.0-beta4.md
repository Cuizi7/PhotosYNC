# PhotosYNC 0.1.0 beta4

PhotosYNC 0.1.0 beta4 (build 4), macOS 13+, Universal arm64/x86_64.
本包为本地 ad-hoc 签名版本，未作 Developer ID 签名或公证。

## 修复

1. pending 队列改用稳定的 `created_order` 游标逐项读取，避免每导入一张都反序列化完整 pending 队列。
2. Photos 候选索引支持按变化增量维护，并按文件名取候选；GUIQA readonly 路径缓存候选快照，避免每个文件重复枚举整套图库。
3. 扫描和 drain 的重复判定在 SQLite 最终提交前绑定 Photos 快照 generation；发现图库变化时事务回滚、重新取快照并重新判定，避免写入过期的 skipped/evidence。
4. 增加 keyset 游标、恢复、候选快照变化和事务回滚的回归覆盖。

## 验证记录

本包由合并后的 main 提交归档构建。发布脚本会在同一归档中重新运行完整 XCTest、合成数据工具测试和 continuation-race，然后构建并核验 Universal Release app、嵌套签名、图标、DMG 和 SHA256 校验值。确切提交、测试数量、工具链和校验值见产物 `PhotosYNC.provenance` 与 `SHA256SUMS`。

本次合并后自动验收已通过：242 XCTest、21 个工具测试、continuation-race 通过，源码 manifest 在验收后保持不变。

## 边界与未验证项

源目录仍严格只读，Photos 仅新增资产；不重判历史 skipped，不清理或迁移生产数据库，不增加内容哈希、自动挂载、Photos 删除/覆盖或复杂调度。真实 Photos 导入、授权变化时序、网络挂载、原生菜单交互、键盘/VoiceOver、macOS 13/14 实机、系统通知和 Developer ID/公证仍需独立验收。

独立代码审查还记录了三个 P2 后续风险：生产 validity token 尚未在提交边界复查授权/图库可用性；增量索引快照可能触发 Dictionary 写时复制；`PhotosCandidateSnapshot` 的显式 validity 仍提供 `AlwaysValid` 实现。它们不影响本次自动验收结果，后续修复应在新的提交中重新审查。
