# PhotosYNC 0.3.0 beta8

版本：0.3.0 beta8（build 25），最低 macOS 13，Universal arm64/x86_64。本地 ad-hoc 签名 App／DMG；实际源码、完整验证和校验值以随包 provenance、validation、SHA256SUMS 为准。

## 本版变化

- Live Photo 身份识别达到固定读取上限时正常跳过，不再提示“需处理”、保留专门 hover 或要求无效重试。跳过计入已处理数量，但不伪装成识别成功或没有配对身份。
- schema **v12** 将旧的、具有当前资源上限证据且无其他读取失败的识别记录迁为跳过，不读取媒体或重新枚举图库。同一资源重启、立即扫描均不重读；变化后仍按正常增量规则重新排队。
- 每 30 分钟维护在当前实例连续监听、上下文/代次相同、无待处理变化且已有有效发布时，省略全库 catalog 遍历。保持索引可用和已知进度；启动、显式请求、监听间断或证明不足仍走完整核对。
- 任务 hover 采用已审核的“标题 + 一句正文”，移除长说明、第二段和滚动；来源离线及视觉解码内存上限保留独立、可操作的提示。
- 同时有正常配对和需处理项目时，说明优先解释需处理原因；暂停后仍在完成的图库提交显示准确的收尾状态。
- 日志区分维护触发原因、无变化快路径、实际已识别和正常跳过数量。

精确配对、原资源验证、未知提交和替代清理保护保持不变。已有原生 Live Photo 无法读取身份时，不将其当作“没有同一配对”的证据；已确定配对的创建/验证超限仍保留原有保护和预留，不扩展为跳过保存结果。普通图像/视频的导入规则与视觉内存设置未改变。

## 升级与验证

退出旧应用后备份完整 `~/Library/Application Support/PhotoSync/`（包括存在的 SQLite WAL/SHM），再安装。新版本启动时事务化升级到 v12；旧版本拒绝 v12，不能直接降级。打包过程不迁移生产数据，也不安装或启动应用。

开发及原生假数据 UI 证据见 [验证记录](../validation/2026-10-24-beta8-task-state-hover.md)。最终发布从 main 的确切归档执行 `scripts/package-release.sh --scale-profile full`，包含完整 XCTest、Tools、四档规模、两组续体竞态及版本、架构、图标、签名、DMG 和校验门槛。随包新证据通过后才确认交付成功。

UI 验证使用实际 SwiftUI 视图与隔离假状态，不等于本机真实图库、原生物理 hover/键盘、VoiceOver 或 macOS 13/14、Intel 实机验收。本轮未扩大 PhotoKit 写入、系统权限、真实媒体读取接口或平台范围。本地 ad-hoc 签名不代表 Developer ID 签名或公证。

交付目录：`outputs/releases/0.3.0-beta8/`。不覆盖旧包，不进行远端推送或公开发布。
