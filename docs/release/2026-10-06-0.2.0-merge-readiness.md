## 本轮后端研究对合并清单的影响

独立实验在本机 macOS 27.0.1 未复现 FP32 `.all` 崩溃，不能将其推断为根因已修复。研究 FP32 CPU 的全部 42 个向量 SHA256 与最新产品 canonical 的 `model-regression.json` 完全一致，确认比较基线未因复制预处理而漂移。

八种精度/执行选项均通过当前 33 例内容与动作回归；64 组 query/gallery 混合对照也未翻转标签。连续负载中，FP32 CPU 500 次 P95 43.35 ms，FP32 GPU 1,000 次 19.67 ms，FP16 CPU+ANE 2,000 次 4.72 ms；这是独立模型进程的暖推理，不是完整导入时延。Instruments 取得了 FP16 的实际 ANE 执行记录。它们支持加速方案，但不证明长期能耗、所有硬件或所有照片的误判率。

既有四个 TorchScript 转换 golden 对照中，FP16 ANE/GPU 均 4/4 通过，FP16 CPU 仅 2/4 通过。这说明固定照片案例全通过仍不足以许可任意 CPU 降级。`.cpuAndNeuralEngine` / `.cpuAndGPU` 是允许的设备集合，也不能单凭配置名字保证没有内部 CPU 执行；最终方案需要实际可验证的加载/数值检查与明确失败行为，而非仅改 `.computeUnits`。

详细方案见 [Core ML 加速研究](../research/advanced-dedup/2026-10-06-coreml-acceleration-research.md)。如果采用新的模型/执行契约，必须在新产品实现上重跑对应转换、回归、资源/包身份和完整自动验收；当前研究报告不替代该验收。

六张用户照片 `images/user-01-1.jpg` 至 `user-03-2.jpg` 已在本地 Git 跟踪及分支历史中；当前 [素材许可记录](../../Tests/Fixtures/AdvancedDedup/LICENSES.md) 明确为 `local_testing_only`。仓库是公开的，因此 **直接推送当前历史会公开这些文件**；仅从 App bundle 排除不解决仓库公开问题。需要先落实适用的贡献许可，或设计保留本地私有回归、公开集合单独绑定的分发方式。若改为排除，必须处理将要推送的历史和清单身份，不能只删工作树文件，也不能擅改 33 例真值来制造通过。本次未推送或上传。

## 不应重新打开的工作与保留的限制

- 0.98 是用户选定的运行阈值；不重启已取消的独立校准和 36,887 个负例收集。现有 33 例不被解释为总体误跳过率证明。
- 不重做 SQLite/常驻缓存选型、P10/P11 已完成实现或全分支等价审阅。若后端方案不影响 SQLite，现有纯查询和差量语义证据继续适用。
- 100k 真实资产及编辑比例矩阵、长期能耗/资源观察仍未完成；合成规模测试不可替代这些声明。本次不擅自追加大规模个人图库试验。
- 61 MP 16-bit PNG 的 2.22–2.46 秒单次准备、日志签名表随本进程接触文件增长、密集高相似候选的最坏情况，以及全量对账仍为 O(N)，继续作为已知性能范围披露；不把研究最优数字当作全格式/全负载保证。

建议顺序：独立后端研究并确定方案 → 必要实现及小 UI 修复 → 最终模型平台/PhotoKit/iCloud/原生交互的针对性检查 → 更新交接记录、最终源码审阅与一次完整验收 → 按选定的本地合并或公开 PR 路径交付。版本与打包工作可在相应发布授权下衔接，不和技术验收混为一项。
