# PhotosYNC 0.2.4

版本配置：0.2.4 stable（build 12）。最低 macOS 13，arm64/x86_64 Universal。本文说明本版范围；实际源码、完整验收及产物校验值由确切干净 main 归档生成的 `PhotosYNC.provenance`、validation 和 `SHA256SUMS` 绑定，不能由版本配置或历史日志推断已经发布。

## 本版改进

- **来源根失联时停止新工作。** 根目录不可访问时，该来源只展示根目录问题，暂停其新读取/提交；健康来源及 Photos 索引继续。独立文件/子目录问题保留，已发送到 PhotoKit 的结果继续落库。恢复期限到期只允许重新检查，实际根枚举成功后才恢复接纳；手动扫描沿用现有立即检查规则。根可用时，单个坏文件仍独立处理。
- **模型输入有成功基线。** 每次图库重算在既有预处理完成后，对实际送入模型的同一 320×320 Float32 NCHW tensor 计算 SHA-256，原始版/当前版、图库 context/epoch 各自独立。仅被现有任务身份检查接受的结果，才能与向量在同一事务内比较和更新成功摘要；失效、descriptor 更新、失败、取消和旧任务结果不能覆盖成功基线。没有新增取图、解码、预处理或推理轮次。
- **明确四种比较结果。** `same_input` 表示同一合同下模型输入相同；`different_input` 表示输入不同；`missing_baseline` 表示没有旧基线；`incomparable` 表示输入管线/运行时合同不可比。旧诊断接口还可报告 `missing_input`。摘要仅用于诊断，不用于跳过计算、保持 ready、放宽失效或更改判重。
- **原因和耗时更完整。** 匿名采样把历史/实时观察、实际失效、任务尝试和被接受结果关联起来；中性通知不能替换待处理的内容义务，混合、缺失或未知范围仍明确标记。历史 updated 不等于像素编辑；实时 `assetContentChanged` 与可见输入/元数据字段差异分别保留。完整比较计数不受采样上限影响；分段耗时以单调时钟 count/sum/max 聚合，失败和取消也保留已执行阶段。日志不输出原始输入摘要、资产 ID、token、图像、EXIF 或新增路径信息；既有系统错误/来源诊断仍可能含操作元数据，分享日志前须检查。

相同模型输入不能证明高分辨率原图所有像素未变。不同输入也不能单凭摘要归因于 PhotoKit 像素编辑：资源选择、解码、方向、色彩及媒体变化仍是分别核对的可能性。计时是含排队/服务等待的 elapsed wall time，不是 CPU 或 iCloud 下载测量；父阶段与子阶段可能重叠，不能直接相加。

## schema v9 与升级

从 v8 到 v9 的兼容事务迁移只在 `photos_representation` 增加可空的 32 字节 `input_digest` 及独立 `input_digest_contract`。保留现有向量、任务、索引/检查点、排除事实、成功历史和 unknown 提交，不新增全库任务、不清理数据库、不强制全库重读或重建。旧记录暂时没有摘要，只有按正常调度成功重算后才逐步建立基线；在此之前出现 `missing_baseline` 是预期行为。

摘要合同独立绑定输入、解码、方向/色彩/预处理、配置及系统运行时，不会因当前 descriptor 或 fingerprint_version 更新而替旧摘要冒充版本。系统/管线合同改变时保守记录 `incomparable`；摘要基线可跨重启，运行内匿名原因链不跨重启持久化。

首次启动新版本前，正常退出 PhotosYNC，备份完整 `~/Library/Application Support/PhotoSync/`，包括 SQLite WAL/SHM 配套文件。**旧 App 拒绝 schema v9，不支持直接降级。** 在新增导入后恢复旧数据库可能丢失成功证据并造成重复新增，不应将旧库回填当作无损回退。更早版本仍沿用既有 v3–v8 迁移步骤，再进入 v9。打包不读取、备份或迁移生产数据库。

## 保持的边界

模型、0.98 阈值、Photos 原始/当前编码资源选择、完整索引就绪与保守失效规则、媒体范围、权限、bundle identity、来源只读/Photos 仅新增均不变。本版不修改重复 reconcile 调度，也没有根治重复历史保守失效。0.2.3 的重试、公平批次及物理 owner 规则保留；没有终止回调的系统请求仍可能需要后续处理，不保证自动恢复，也不会强制释放或创建替代读取器。
