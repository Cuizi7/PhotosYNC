# PhotosYNC 0.2.0 beta

版本配置：0.2.0 beta（build 7）。最低 macOS 13，交付目标为 arm64/x86_64 Universal app。本页记录发行范围与使用边界；版本配置不代表发行包已经生成。最终源码提交、完整验收结果与校验值须以本次包内的 `PhotosYNC.provenance`、`validation/validation.json` 和 `SHA256SUMS` 为准。

## 本版变化

- 照片使用随包提供的 SSCD Large FP16 模型生成指纹，输入、输出和持久化向量为 Float32。Apple Silicon 请求 CPU + Neural Engine，允许一次降级到 CPU + GPU；Intel 选择 CPU + GPU。每个新模型实例先通过四组固定数值自检，没有应用层 CPU-only 兜底。请求配置可以内部调度 CPU，不能据配置名称声称实际硬件执行轨迹。
- 使用系统 SQLite + Accelerate 对有效候选精确评分。照片可跨文件名判重；用户选定 `score >= 0.98`，并保留更高分辨率副本的导入规则。现有固定 33 例回归不等于独立统计校准，误跳过率没有得到统计证明。视频继续使用原有文件名与元数据规则。
- 原生菜单栏面板显示图库分析进度。首次索引就绪后才开始导入；Photos 原始版和当前编辑版分别参与候选。常规图库变化按资产维护指纹，核对不确定时保留向量、任务和成功历史，撤销旧候选发布，确认连续性后再使用。未决通知及临时历史保护窗口等待重新核对，真正失效仍保守阻断。
- 单项 PhotoKit 图像读取错误持久化分类并隔离，其他健康项继续处理。存在读取缺口时，可用候选覆盖不完整，可能漏掉仅由缺失表示证明的重复；报告和日志须保留这一限制。未知历史错误不能仅凭文本转成允许跳过的缺口。
- 模型资源固定版本、随包分发并经本地 Git LFS 对象和构建后资源校验。读取有界，允许按需获取 iCloud 图像；512 MiB 解码预算外的可读静态图片采用保守原始导入。完整原片不会被批量下载用于判重，也不建立应用原片缓存。

来源文件仍严格只读，Photos 写入仅新增资产。成功导入历史和未确认提交保护继续有效；不配对 Live Photo、不转码、不删除或覆盖既有资产、不自动挂载网络来源。

## 升级前备份与降级边界

0.1.0 使用 schema v3；本版首次打开应用数据库时事务化升级至 v7，保留来源配置、成功历史、未知提交与现有恢复事实。升级失败应整体回滚，未知更高版本数据库拒绝打开；不得删库重置。升级后的候选仍须重新证明清单与变化覆盖，不能凭已有字段直接复用旧发布。

**首次启动新版本前，请正常退出 PhotosYNC，并备份完整的 `~/Library/Application Support/PhotoSync/` 目录**，包含 `sync.sqlite` 及仍存在的 `sync.sqlite-wal`、`sync.sqlite-shm` 等配套文件。确认备份完成后再启动；不要在应用运行时只复制数据库主文件。打包脚本不会启动应用、执行此备份或迁移生产数据库。

旧 0.1 应用会拒绝 schema v7，不能直接打开升级后的数据库，本版不承诺直接降级。不要删除升级库、回填旧 schema 或自行恢复旧备份来绕过拒绝；升级后的导入可能已新增 Photos 资产，旧备份不包含这些成功记录，恢复它可能导致再次导入。备份保留升级前证据，并不等于已有跨版本回滚方案。

## 验证状态与已知缺口

既有开发源码的完整自动验收、实际模型回归、合成规模和受控竞态证据见[高级判重验证记录](0.2.0-advanced-dedup-validation.md)、[连续性验证](2026-10-07-photos-index-continuity-validation.md)和[单项读错及历史竞态修正记录](2026-10-08-photos-read-error-isolation-validation.md)。历史通过不能替代本次归档的验收，测试数量由本次报告记录。

真实 Photos/iCloud 只读 QA 已发现并驱动索引连续性、通知恢复和单项读错修正，但全库可用候选覆盖、MobileBackup 端到端判重、视觉抽查及最终有界写入/回滚尚未完成。最新范围以[真实图库验证计划](2026-10-06-real-photos-icloud-validation-plan.md)为准，不能宣称真实图库验收通过。读取缺口和重新验证进度也不能算作完整索引就绪。

macOS 13 与 Intel 实机的 0.2 Core ML/PhotoKit 行为未验证；两项实机验证均按用户指示不在本轮执行，不作为本轮本地 beta 收尾条件。最低支持版本仍为 macOS 13；Universal 构建及最低部署目标检查不能替代实机运行。完整原生键盘、VoiceOver、popover 和系统权限路径仍有验收缺口。合成数据的性能预算通过不保证每张大图、网络来源或 iCloud 获取都在两秒内完成。

本地包采用 ad-hoc 签名，未进行 Developer ID 签名、公证、stapling 或 Gatekeeper 验收；换新构建后 macOS 可能要求重新授予照片权限。本次发行准备不构成安装、启动或系统权限实测。

## 本地发行入口

`scripts/package-release.sh` 要求干净已提交源码，先从确切提交归档并校验本地 LFS 资源，在同一归档中执行完整 XCTest、Tools、模型/规模与两个 continuation 回归，再正常构建 Universal Release app；继续强制核验图标、模型资源、逐层签名、DMG 和 SHA256。缺工具、失败、超时、零测试或资源损坏均不能跳过。

唯一目标目录为 `outputs/releases/0.2.0-beta/`，包含 `PhotosYNC.app`、`PhotosYNC-0.2.0-beta.dmg`、`RELEASE-NOTES.md`、`CHANGELOG.md`、验证证据、`PhotosYNC.provenance` 与 `SHA256SUMS`。已有目录、文件、符号链接和发布锁均不得覆盖。此准备阶段尚未生成该发行包，也未安装或启动应用。
