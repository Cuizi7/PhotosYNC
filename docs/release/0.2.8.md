# PhotosYNC 0.2.8

版本：0.2.8 stable（build 16）。最低 macOS 13，arm64/x86_64 Universal。确切发行源码、验证结果及产物身份由本次 `PhotosYNC.provenance` 与 `SHA256SUMS` 绑定。

## 本版修复

- **目录不可用直接展示。** 来源根目录不可用时，主菜单和设置直接显示警示图标与“来源目录不可用，等待恢复”；部分子目录故障显示“部分子目录不可用”。目录和连接状态不再被合计成“发现 1 项问题”。
- **文件问题独立计数。** 主菜单、设置和诊断详情共用两层投影；“X 项问题”只统计文件读取/解析、文件导入/提交诊断。相同路径的不同诊断身份仍独立保留，目录故障与文件问题并存时分别展示。
- **恢复提示对应实际工作。** 没有剩余目录诊断、但完整遍历尚未完成时，当前来源确实处于扫描阶段才显示“正在扫描目录”；暂停、延后或空闲时显示“目录扫描尚未完成，稍后继续”。其他来源或导入提交的工作不能冒充当前目录正在扫描。

沿用已有目录与文件两层检查、根目录读取/提交准入、文件重试和完整遍历恢复门槛。根目录失联期间只投影根诊断，独立文件证据保留，恢复后按原规则显示、核对或解除。

## 升级与数据库

沿用 **schema v10**，本版不新增迁移、不清理生产数据。已有任务、分析成果、成功导入历史和未知提交保护保持既有规则。模型、0.98 阈值、增量分析、媒体读取、来源只读与 Photos 仅新增规则沿用 0.2.7。

升级安装前应正常退出应用并备份完整 Application Support/PhotoSync 目录，包括 WAL/SHM。打包不会安装、启动、备份或迁移生产数据。schema v9 或更早的应用拒绝升级后的数据库，不能直接降级；不要在新导入后恢复旧数据库而丢失成功证据。

## 验证与分发

打包归档先写入本次私有构建目录的源码 tar，再解包，避免解包器正常结束后上游 Git 的 SIGPIPE 被误判为失败。归档、解包、源码绑定及全部后续门槛仍分别检查。

运行时测量夹具按既有有界批次契约，通过后续正常 tick 等到历史项实际导入后再测量；不假设一次 tick 能完成全部原生推理，原有导入数量、读图/推理次数和性能阈值保持不变。

开发快照通过完整自动验收和离屏 UI 回归。正式包从合并后干净 main 的确切提交归档执行完整无过滤 XCTest、Tools、模型/资源门槛、两组受控续体 GREEN/预期 RED，以及正常 Universal Release 构建、逐层签名、DMG 和校验值检查；实际结果以随包证据为准。

本版不涉及索引、候选查询、缓存、SQLite、预处理/模型性能或资源行为变化，明确选择 **release** 规模档：20 万表示＋10 万成功历史，含既有性能阈值、大媒体和 60 秒空闲/恢复检查。本次不是 full 四档规模验收。

本轮新增界面证据为合成状态和离屏 UI 测试。未新增真实 Photos/iCloud、生产数据库迁移、原生菜单交互、VoiceOver、macOS 13/14 或 Intel 实机验收；历史证据不写成本包的新实测。

公开资产为 `PhotosYNC-0.2.8.dmg`、`PhotosYNC.provenance`、`RELEASE-NOTES.md`、`SHA256SUMS`；公开校验文件覆盖前三个载荷，完整本地验收证据另行保留。采用 ad-hoc 签名，未进行 Developer ID 签名、Apple 公证或 Gatekeeper 验收。
