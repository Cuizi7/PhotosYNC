# PhotosYNC 0.2.5

版本：0.2.5 stable（build 13）。最低 macOS 13，arm64/x86_64 Universal。源码、验证和产物由同一干净 main 提交归档构建，实际结果见随包的 `PhotosYNC.provenance` 与 `SHA256SUMS`。

## 本版改进

- **保留连续分析中已完成的指纹。** Photos 实时通知已确认内容未变时，后续完整图库核对沿用连续观察结果，不再因历史记录只有通用“更新”信息而反复要求重算。大量已分类通知和通知缓冲溢出仍可触发图库核对，但不会自动作废所有已完成指纹。
- **避免重复完整核对。** 已由成功清单处理覆盖的核对请求不会再次触发整库遍历；稍后到达的新请求、手动扫描、权限恢复及定期核对仍保留。
- **保留真正变化的安全检查。** 内容编辑、缺失的变更信息、变更记录持久化失败、图库不可用和权限中断仍走保守恢复；即使分析暂停时没有发生取图调用，权限转换也会撤销旧确认。完整索引就绪要求保持不变。另修复了订阅取消与通知发送同时发生时的锁等待问题。
- **日常发布减少重复规模采样。** 常规发布默认只运行二十万条表示加十万条成功历史的规模场景；索引、查询、模型或资源等相关变化仍使用完整四档。本版修改了索引行为，发行使用 `--scale-profile full`，不缩减其规模验收。完整 XCTest、工具、模型、恢复竞态和产物检查仍必需。

## 升级与使用边界

从 0.2.4 升级继续使用 schema v9，不增加迁移，不清理已有向量、任务或成功导入历史。旧版本已经标记为未验证的工作仍需完成验证，不能直接恢复显示为已完成。

连续运行期间保留最后安全恢复的历史检查点。重新启动或真正失去观察连续性后，会保守核对检查点以来的变化，因此仍可能重验部分已计算照片。实际内容编辑同样会让相关进度重新等待处理；本版不承诺任何情况下进度永不下降。iCloud 取图等待仍可能发生，系统请求始终不结束时仍不保证自动恢复。

模型、0.98 阈值、图像获取与缩放实现、来源只读、Photos 仅新增以及成功导入记录保护均保持原规则。更早版本沿用既有 schema 升级和降级边界。

## 验证与分发

开发阶段已通过索引连续性、部分建库逐步完成、中性通知、大批及溢出通知、真实内容编辑、权限恢复、旧确认拒绝和重启恢复测试。两条请求竞态使用受控任务等待，并通过故意移除保护的反向测试确认检测能力。正式发行须在本次 main 归档内执行完整四档验收和 Universal Release 构建，不能用开发结果替代发行记录。

公开资产为 `PhotosYNC-0.2.5.dmg`、`PhotosYNC.provenance`、`RELEASE-NOTES.md`、`SHA256SUMS`；公开校验文件覆盖前三个载荷。本地完整验收证据与完整校验清单另行保留。

本版沿用 ad-hoc 签名，未进行 Developer ID 签名或 Apple 公证。macOS 13 和 Intel 实机验证仍未执行。此次发布不安装或启动生产 App，不操作生产图库；真实图库整夜运行效果仍需升级后的生产观察确认。
