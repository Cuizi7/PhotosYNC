# Model input diagnostics: validation boundaries

This unreleased change starts from merged PR #6, main `02d4e4ec3d92343811054cb410d8ee27b50f02ed`. It changes no version, model weights, threshold, Photos resource selection, scheduler or physical reader owner policy. No production app, source, Photos library, database, mount or permission is used in its tests. No installation, merge or release is implied.

## Persistence and evidence

Schema 8 to 9 transactionally adds nullable `input_digest` (32-byte BLOB) and independent `input_digest_contract` columns. Existing descriptors, vectors, tasks, index state/checkpoint and import history are retained exactly; migration creates no new fingerprint tasks. Upsert, invalidation and failures retain the last successful baseline. Only the existing current store-issued task guard can replace a baseline, in the same transaction as vector completion. Rejected results cannot update it; transaction-failure tests prove rollback. The legacy fingerprint completion API retains baselines when no digest is supplied. Older apps reject schema 9.

The SHA-256 stream is the actual prepared tensor's logical Float32 NCHW elements serialized little endian, excluding padding. The separate contract binds serialization, resource/decoder/orientation/preprocessing rules, configuration/model and the OS/framework runtime. Transform or decoder policy changes require updating the diagnostic contract namespace even when the fingerprint policy does not change. An OS/runtime change conservatively produces `incomparable`. Old rows remain `missing_baseline` until a normally scheduled successful task supplies evidence; this change does not force a full-library read.

`same_input` proves only the model input is identical within that contract, not full-resolution original-pixel identity. `different_input` does not isolate a cause: resource choice, decode, orientation, color and media edits remain separate possibilities. Persistent updated IDs retain unknown content scope; live `assetContentChanged` and public input/metadata field-name differences remain separate facts with no values logged.

Causal detail uses at most eight sticky anonymous assets, 64 records per operation, and 64 new cause rows per 30-second run window. At most four pending obligation observations per sampled asset, plus bounded per-kind invalidation bindings, accepted watermarks and captured issuances, bound correlation memory. Neutral observations are still counted/logged but cannot replace pending content provenance. Actual transferred invalidations bind context, index/Photos generation and descriptor/issuance revision; full-scope continuity loss is explicitly unknown, and multiple/omitted obligations remain mixed/unknown. Context/epoch checks prevent cross-library inheritance. An attempt captures its cause, so later events cannot rewrite late physical/result diagnostics. Across restarts the successful SQLite baseline survives; run-local cause chains intentionally do not. Complete comparison counts are independent of sample/detail admission and still accumulate with a disabled sink. Operation summaries bind the inventory context/generation; global timing/cause summaries explicitly cover a run window.

## Focused synthetic evidence

Actual preprocessing plus SQLite tests cover all comparison outcomes, original/current and context/epoch isolation, descriptor/version changes retaining old contracts, invalidation, retries/failures, stale/reissued tasks, reopen continuity, migration parity/future-schema rejection and transactional rollback. The coordinator fixture performs four recomputations with four image reads and four predictions; no diagnostic reacquisition or extra inference occurs. The digest helper itself performs no image acquisition, decoding or preprocessing.

Representative optimized scratch probe: exact production preprocessor/configuration/digest helper, 100 iterations of a 320 × 320 × 3 Float32 tensor (1,228,800 bytes). Digest mean **1.52 ms**, maximum **5.43 ms**; one fixture preprocessing about **4.80 ms**. These are local monotonic wall measurements, not actual model, Photos or disk/network throughput. Debug instrumentation was much slower (about 69 ms/digest), so optimized and Debug timings must not be mixed. Temporary probe source and mutation evidence are retained under ignored `work/tensor-probe/`; no probe code enters the app.

Eight-hour synthetic notification stream: **13,440 bounded rows** (8,640 pre-existing observation rows, 3,840 cause rows, 960 window summaries). With 11 explicit control rows, JSONL totals **4,936,399 bytes**, about 0.62 MB/hour in that fixture. All 3,840 causes remain counted. Sample-cap/disabled-sink tests count 1,000 accepted comparisons without retaining per-asset history. Executed preprocessing, digest, model-queue and prediction stages also report on failure and cancellation through a per-call bounded hook; original errors remain unchanged, failed/cancelled results never advance the baseline. Fixed-stage timing summaries use count/sum/max; stages are monotonic elapsed wall time including queue/service waits, not CPU. Catalog/history/fingerprint totals can contain the measured child phases and must not be summed with them. No draining wait is labelled as iCloud.

Focused build/test logs and retained RED evidence live in ignored `work/`: `tensor-final-*` (22 tests), `store-focused-green-tests.log` (123 tests), `gateway-final-*` (57 tests), and `parent-integrated-green-*` (77 tests before the final scope-summary assertions). The review fixes add `tensor-review-final-*` (28 fingerprint tests) and `parent-review-green2-*` (138 gateway/coordinator tests), with controlled RED failures retained in `parent-cause-review-red-*` and `tensor-review-red-*`. They cover content→neutral→attempt, old-specific→unknown-full invalidation, bounded mixed/future provenance and actual prepare/hash followed by failed/cancelled prediction. These runs are development evidence, not final complete acceptance. The final integrated independent review, frozen source SHA/tree and fresh `scripts/validate.py` record are supplied in the PR and local handoff report, without overwriting these earlier logs.

## Unverified boundaries

Real Photos/input changes, production DB migration, UI interaction, macOS 13/14 and Intel hardware, signing/distribution and release packaging are not newly tested. Synthetic/fake lifecycle evidence does not claim these passed. Baseline bytes in the application database are diagnostic data; raw digests, asset IDs, paths, tokens, EXIF and media are not emitted by the new logs.
