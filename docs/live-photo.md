# Live Photo

默认保留照片、动态和原有声音，导入为一个原生 Live Photo；没有开关，不转码。只有 HEIC/JPEG 或 MOV 时先按普通媒体保存，找到精确另一半后补齐；同样适用于图库原有单项。缺半本身是正常情况。

## 识别与首次覆盖

- 照片 Apple Maker Note 身份与 MOV 的非空 ContentIdentifier、实际 still-image-time 样本匹配，再验证资源角色与版本。文件名、时间、视觉相似只可发现候选，不能证明配对或授权删除。同 ID 多版本保留歧义。
- 普通视频 **大于 10 秒**跳过身份识别，仍正常导入；10 秒整、时长未知、原生 Live Photo 或已有当前精确身份不排除。这是应用规则，不是 Apple 格式上限。
- 首次任务使用固定键，枚举授权图库及核对已有记录，逐项尝试并衔接变化后持久化完成。常规重启/升级不重开首次任务；未完成项续跑。无启用来源仍可处理 Photos 内的历史配对；停用来源不读源文件。
- 完成首次覆盖不等于每项识别成功。变更、未解决资源仍单项核对；**当前历史更新回放可能大批重排已识别项，尚未修复**，见[已知问题](README.md#当前未解决)。公开 API 没有连接 PHChange 与持久历史的共同事件 ID；稍后采样的 token、相同 descriptor/date 均不能证明原资源未变。
- 精确身份在普通判重前登记，静态图片重复不等于 Live Photo 已完整。首次识别与潜在原生完整候选未核实前不创建重复完整目标；保留已配齐资源，不因等待拆成两个单项。普通单项导入不等待全库识别结束。

## 补齐与清理

没有公开的原位追加另一半接口。用一个 `PHAssetCreationRequest` 加入 `.photo` 与 `.pairedVideo` 创建完整资产，再验证、清理，资产 ID 会变。

1. 固定上下文、精确资源版本、旧资产及属性/相册快照，事务预留源成员；普通导入路径不能抢占。
2. 创建或复用精确完整目标；先记明确成功，再验证 LIVE subtype、资源身份、播放对象及音轨。已有成功不因后续验证失败撤销。
3. 只有原资源和受保护信息均已保留，才持久化清理意图、另发精确删除请求；不能清空“最近删除”或删除完整 Live Photo。
4. 中断后只续未完成阶段。已验证新目标只有精确覆盖旧尝试时才结清旧阻断；unknown 或未覆盖操作不得顺便解除。

**删除条件全部成立才可清理：**

- 新建目标实际使用旧资产的精确 Photos 原资源；复用目标时逐字节流式比较。源 stamp、配对 ID、成功历史都不能替代原资源证明。不存内容哈希。
- 新旧 revision 未变，旧项无无法迁移的编辑、额外资源或共享相簿关系；任何未知信息都不能当作空。
- 日期/位置、收藏/隐藏、评分、说明、关键字和普通相册已知且保留。创建时相册取并集，收藏/隐藏取或，日期/位置取照片端；冲突或无法保留则留旧项。复用目标不能静默改其属性来满足条件。
- **标题不保护**：标题未知、不同或单独变化不阻止清理，旧标题可能丢失。人物、回忆、外部引用等未公开关联不在迁移保证内。

保留受保护旧项是正常结束，不持续报警。创建/删除未知则保留意图并全局阻断新写入；查询缺失或匹配删除事件不能单独证明成功。外部删除已关联成员/完整目标会停止该组自动补齐，避免复活用户删掉的内容。

## 资源与推进

- 按需读取 iCloud 原件；Photos 临时资源合计 **512 MiB**、磁盘保留 **128 MiB**，与图片解码内存设置不同。MOV 不进图片解码管线，源文件不暂存。
- 请求期限 600 秒、逻辑期限 610 秒；真实 terminal 前仍持有物理资源。临时失败逐项 60 秒重试，容量暂占走正常 deferred。
- 身份识别固定资源超限是持久正常跳过，计已处理但不算身份已读；无警告/独立 hover，重启/立即扫描不重读同版本，资源变化后重试。它不能证明不存在完整候选。解析失败、解码内存限制、组验证超限与 unknown 不冒充这种跳过。
- 单 worker 串行读取，每片至多 16 轮；有进展继续下一片，无进展退出。最多连续优先 8 个到期原生候选后让普通项前进，不提前拉起未来重试。
- 通知分类短暂未完成可保留 1 份原资源及 1 项部分解析结果最多 30 秒；复用前重验。变化、未知覆盖、暂停、取消或到期就释放，不能因缓存跳过安全守卫。
