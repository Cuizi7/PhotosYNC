# PhotoKit representation contract (P2)

Checked on 2026-10-05 with Xcode 26.6 / Swift 6.3.3 and the local macOS 26.5 SDK, deployment target macOS 13. This is SDK, synthetic bitmap, injected callback and fake catalog evidence. It is not a real-library/iCloud or macOS 13/14 runtime acceptance result.

## Version, size and orientation

`PHImageRequestOptions.version` explicitly selects `.original` or `.current`; the request uses `.highQualityFormat`, `.exact`, `.aspectFit`, asynchronous delivery and `isNetworkAccessAllowed = true`. Only the first non-degraded, non-error, non-cancelled bitmap completes successfully. Error, cancelled, nil and over-budget images fail. Repeated terminal callbacks cannot publish or normalize another image.

The app draws the delivered **NSImage's displayed contents** through `NSImage.draw(in:from:operation:fraction:respectFlipped:hints:)` into a bounded, 8-bit sRGB RGBA CGContext. Its output is normalized pixels with orientation `.up`. It never extracts a backing CGImage and assumes EXIF was already applied. Synthetic asymmetric JPEGs tagged with all eight EXIF orientations are drawn and compared with ImageIO's explicit orientation-transform reference, including rotated dimensions and quadrant colors. They cover AppKit native drawing, not the Photos service's rendering of edited/iCloud assets.

The descriptor's size comes only from the uniquely selected `PHAssetResource.pixelWidth/pixelHeight`: `.photo` for original, `.fullSizePhoto` for edited current; original may supply current only when there is no adjustment resource. Unknown, ambiguous or absent dimensions remain nil. The actual bounded bitmap dimensions are separately exposed as `LoadedRepresentation.returnedSize`; they never overwrite descriptor dimensions. `PHAsset.pixelWidth/Height` are current-version asset metadata and are not borrowed for original. Resource dimensions are available from macOS 13 in the checked SDK. RAW+JPEG `.original` may choose RAW; the original slot is explicitly excluded rather than pretending the JPEG was selected.

## Static component eligibility and exclusions

Public `PHAsset.playbackStyle` distinguishes `.image`, `.imageAnimated`, `.livePhoto` and video styles at the deployment floor. JPEG, PNG, HEIC and HEIF with `.image`, or the approved `.livePhoto` still component, are eligible when there is one unambiguous selected still resource and no alternate still resource. HDR/depth auxiliary data and the Live Photo paired video do not by themselves exclude the primary still. We do not fingerprint or pair the video component.

Animated playback, alternate/ambiguous still resources, GIF/TIFF and unverified containers such as PSD are conservative. A rendered first frame is not evidence of equivalent full container content. RAW is explicitly unsupported. `RepresentationPage.descriptors` contains usable still slots; `exclusions` carries `RepresentationCatalogExclusion(descriptor, reason)` for known RAW or conservative slots. Pagination advances across **all original/current slots**, including exclusions; `descriptors.count + exclusions.count <= limit`. No Photos error is converted to an exclusion.

A current version can remain eligible when its original is excluded. P3 must count an entire asset as excluded only after all slots are reconciled and none is eligible. P3 must never persist conservative output as a normal ready vector. Any unexpected post-read `LoadedRepresentation.eligibility.conservative` means waiting/reconciliation until a current catalog establishes the exclusion. P4's source-container classifier must inspect actual bytes; it must not infer source frame semantics from a rendered candidate bitmap.

## Revisions, generation and continuity

**Design amendment, 2026-10-07 — not implemented or accepted yet.** The former P2/P11 implementation treats some full-reconciliation/overflow conditions as all-vector invalidation. The rules below replace that coupling; the prior SDK/component test record is historical evidence, not acceptance of this amendment. The authoritative product design is spec §4.1–4.4.

The current revision is SHA-256 of public resource descriptions and the exact modification-date value, not an opaque content version or image-content hash. Its existing `revisionIsReliable` flag only checks that required facts exist. Equal signatures alone do not prove unchanged pixels across a lost or unknown change interval. Reuse requires confirmed context, representation/input semantics, fingerprint version and covering content-continuity evidence; known content changes override an equal signature. A missing proof makes the entry unverified, not absent or distinct.

Separate three effects: catalog reconciliation required, specific representation content invalidation, and withdrawal of publication/decision permission. An unclassified observer event promptly withdraws potentially stale decisions. `fullReconcileRequired` requests a fresh lightweight catalog and continuity check; it must not by itself clear vectors or invalidate every active input. Once classified, an unrelated change or a proved non-input metadata change cannot reject a valid per-item read/inference solely because the global notification generation advanced. Changed/deleted inputs, revoked authorization, uncertain context and replaced tasks still cannot publish stale work. Unknown active inputs finish/release physical resources; an unprovable result remains pending/retriable rather than ready.

A valid full catalog may preserve existing vectors only with adequate evidence. Real-time details covering the relevant asset/interval, complete persistent history excluding it from changes, and corresponding input/resource checks can support reuse. Persistent updated IDs without content/metadata detail are affected/uncertain IDs, not automatically metadata-only. Original/current reuse remains representation-specific; recompute both for an affected asset when the distinction cannot be proved. Do not infer harmless iCloud/cache activity from timing, event names, unchanged dimensions or filenames.

Bounded event delivery remains required. A queue overflow, missing subscriber, generation gap or nonincremental fetch result sets sticky reconciliation-required state; it does not assert that all image contents changed. Preserve known affected IDs durably in bounded batches before acknowledging their history range. Batch capacity is not the maximum number of changes that can be represented: 129 known IDs must not invalidate 100,000 unrelated assets merely because a batch holds 128. If the complete set cannot be preserved, retain uncertainty and reconcile without erasing cached bytes. No unbounded task/ID/vector heap queue or second database is introduced.

`LibraryResumeCheckpoint { context, archivedChangeToken }` remains continuity evidence followed by mandatory reconciliation, never readiness or a physical-library UUID. Replay coverage must be complete before its endpoint is acknowledged. Pages/checkpoints may carry known invalidated IDs; pending event details and unknown scope instead require validation. `invalidateAllCachedRepresentations` cannot be asserted merely for an unfinished callback, replay-set overflow or a generic full-reconcile wakeup. A genuinely incompatible context/model or unprovable complete old index can require broad rebuilding, with an explicit reason; successful/history/unknown-import evidence is preserved. Expired or unavailable history never becomes a fabricated empty delta.

A stable enumeration identity is distinct from the raw notification sequence and covered change endpoint. Bind pages to one confirmed baseline/fetch-result identity, retain complete classified changes from that baseline, and merge them to a chosen endpoint; neutral notifications alone cannot restart every page walk. The adapter must establish the public PhotoKit baseline/detail relationship, not assume a raw generation is an immutable enumeration handle. Missing or incomplete change coverage still blocks publication. Test a neutral notification between every page with no quiet full-scan window.

A completed, merged catalog plus all required validated representations and covered/classified changes is still required for publication, with the final same-context/current-endpoint acknowledgement tied to the committed index version. Failed or racing acknowledgement keeps publication closed while retaining bytes and progress. Startup, resume and the 30-minute audit stay in place. Only proven unchanged reconciliation has zero representation/task-row writes and zero image/model work. Restart must restore the unfinished/uncertain obligation, not silently promote stored vectors to current candidates.

Apple documents `fetchResultBeforeChanges` as the same object supplied to `changeDetails(for:)`; the identity guard is not to be removed on the assumption that identity is unsupported. `hasIncrementalChanges == false` denotes an excessive change scope, without a published threshold. `assetContentChanged` concerns photo/video content; fetch-result object changes also cover metadata. None of these statements establishes what caused the two real read-time notifications on October 7. Raw details and the producer's specific fallback branch still need diagnosis, separately from implementing this contract.

Additional SDK/API check for this amendment: object-level `changeDetails(for: oldAsset)` may be queried against the same `PHChange` and retained baseline asset. A nil object result documents no object change; a nonnil result distinguishes deletion and `assetContentChanged`. For a nonincremental fetch-result change, enumerating these old baseline objects can provide narrower evidence than assuming that every image changed. This is an implementation inference from the public contracts, not an Apple promise of an atomic full-library snapshot. It remains valid only while the baseline/change association, interval coverage and context hold; compare representation selection, dimensions, equivalence and eligibility before reusing a vector even when content is unchanged. Candidate filename/video metadata still updates.

Persistent object changes expose inserted/updated/deleted identifier sets, without an `assetContentChanged` bit or before/after resource facts. Updated IDs are therefore affected or uncertain, never implicitly metadata-only. Only a fully enumerated history interval can supply negative evidence for IDs absent from its changes. The checked SDK marks persistent tokens/history as available from macOS 13; token expiration or replay failure retains uncertainty. A raw generation integer is process-local, so persisted change obligations also need an explicit restart boundary before any covered-through comparison or cleanup.

## Physical resources and caller duties

A configured gateway receives one immutable DedupConfiguration and the shared `ImageWorkBudget`. The production profile supplies decode concurrency 1, PhotoKit request concurrency 1, 128 MiB app-owned decoded-image budget, maximum 2 in-flight images and 30-second logical timeout. The legacy parameterless gateway keeps v1 behavior and does not enable the advanced reader; P6 must use the configured initializer.

`ImageWorkBudget.acquire(bytes:)` rejects exhaustion rather than queueing unbounded tasks. The image lease holds a counted image and reserved bytes through the final physical consumer. The unchanged targetSide² × 20-byte lease reserves targetSide² × 12 bytes for aggregate exposed incoming rasters and two targetSide² × 4-byte RGBA footprints for the normalization CGContext and returned image. It does not assume makeImage always shares the context storage. For NSBitmapImageRep, checked arithmetic sums max(bytesPerRow × height, bytesPerPlane) × numberOfPlanes across every retained bitmap. Other bounded raster representations use public NSImageRep.cgImage(forProposedRect:context:hints:); the actual returned dimensions and checked bytesPerRow × height join that same aggregate. Nil, malformed, oversized or over-reservation results are rejected before allocating the normalized image. An autorelease pool confines NSImage traversal and temporary raster materializations to the synchronous callback normalization scope; only normalized CGImage plus lease enter asynchronous work. Raster extraction is accounting only; native NSImage drawing still determines the displayed pixels/orientation. The public accessor can allocate inside AppKit before validation: proposed bounds are hints, and exposed raster footprint does not prove all opaque provider/source/cache storage or immediate framework deallocation. Oversized output carries actual width/height in its rejection. The fixed model target comes from the configuration (320), not an independent reader constant.

The request slot ends only on a real terminal callback or a synchronous request-start failure. Logical cancellation/timeout resolves the caller but keeps the request slot and byte lease occupied. We deliberately do not issue `cancelImageRequest`, because PhotoKit may then suppress all callbacks; a never-completing request remains occupied instead of spawning replacements. A late final result after cancellation is discarded and releases resources only at physical completion. The final successful callback releases the request slot but transfers the byte lease with `LoadedRepresentation` until inference/consumption really finishes. Call `await loaded.lease.finishPhysicalWork()` only then, never in a logical-timeout defer. Deinitialization is a fallback; explicit physical completion is preferred.

`ReadExecutor.executeImage(sourceID:budget:bytes:limits:operation:)` retains sourceID fairness and the existing physical source-read slots, additionally limits physical image decodes, and returns `ImageWorkResult(value, lease)`. Source closures keep the lease if the logical caller times out/cancels. Source ImageIO code in P4 must limit thumbnail decode output and reserve bytes before decoding; no original-image temporary files are written by P2.

The budget does not claim to control PhotoKit's internal caches, all decoder working memory, model runtime allocations or iCloud transfer bytes. `.exact` bounds delivered pixels, not downloaded original bytes. Actual service memory/download behavior, adjusted/Live Photo/RAW resource mapping and callback lifetime remain P9 system acceptance work.
