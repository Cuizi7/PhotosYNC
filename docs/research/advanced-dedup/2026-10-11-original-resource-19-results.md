18 组的 Source 文件与 Photos 原始编码资源 SHA256 相同，经共同解码后的 Float32 张量也逐字节相同。剩余 MB-004 的原始编码不同，方向表示也不同：Source 为 3024×4032、EXIF 1；Photos 为 4032×3024、EXIF 6，两者显示尺寸均为 3024×4032。该组仍使用原来的“同一照片副本”标签，新分数 **0.9840663091727172**，旧分数 **0.9662622213363647**。没有修改标签、另找候选或下调阈值。

因此，这 18 组字节相同副本的低分可以由不同取图/缩图路径解释；在这组证据上无需更换 SSCD Large。另一组仍有不同像素输入，虽通过阈值，不把其结果说成所有副本都必然得 1.0。此次是指定配对的内容评分，不是完整图库近邻检索、分辨率覆盖策略或实际导入动作验收，也不代表总体误跳过率/召回率。

## 已测试的路径

```text
Source 原始文件 URL ─────────────────────────────┐
                                                ├→ 同一 ImageIO 解码 → 同一 320×320 预处理 → SSCD
Photos 唯一 original .photo → requestData → 临时 URL ┘
```

两边调用未改动的冻结 Core `MetadataReader.readForFingerprint` 和 `ImagePreprocessor`。共同有界解码最长边 4096，decoded allowance 512 MiB；保留原始 EXIF 方向并共同处理 sRGB、全画面 stretch 和归一化。模型收到 Float32 `[1,3,320,320]`，输出 1024 维向量。取得原始编码资源不等于全尺寸展开所有像素。Photos 此次没有提前获取 320 预览图。

沿用 SSCD Large FP16 包 `026e7a43660e29c307941a88dbe35b9c14468693333ff926e9b984eef3b4b8d0` 和执行策略 `fp16-ane-gpu-v1`；运行选择 `cpuAndNeuralEngine`，四个 golden 自检通过。配置名称不证明全部计算均在 ANE 上。此次私有探针仍绑定旧 fingerprintVersion `ec805406fa61e91384e4bf29ae29a52694b80e3755afd7768da80a6db70c9a1d` 以隔离输入因果，没有发布产品索引；正式切换必须生成新的取图契约/版本，不能混用旧 320 指纹。

当前 active33 的 42 张编码图像另经同一共同解码器和模型：**33 / 33 内容判定符合预期**，14 判重、19 判不重，四个数值自检通过。未修改原 suite/真值，未将内容通过称为高清升级导入动作已验证；这不是 31 个真实负例的新 Photos 原片路径测试。

## 资源与运行证据

19 次 Photos 原始资源合计 **58,030,227 字节（55.34 MiB）**，流式写入私有临时文件。本轮每资源 QA 上限 64 MiB、请求 deadline 30 秒；没有达到上限、没有单项读取错误。源文件/Photos 描述符前后核对通过，所有新临时编码资源在实际完成后删除，19 组都记录 drain，结束时资源、图像、Source 读取槽位为 0。保留的证据是私有张量、无 metadata 的最终输入预览和结果，旧 QA 证据未删除。

独立核对依据逐例删除/占用记录、实际文件清单和已审阅的排他创建/设备与 inode 清理守卫；没有另存被删除临时文件的独立 inode receipt。此限制不改变本次目录内没有编码原片遗留的事实，但不将其称为系统全部文件写入审计。

另以相同 38 个已捕获张量做只增加单调时钟的离线评分：模型初始化、加载及四组自检 **1.742 s**；准备后的单次模型 API 调用 **中位数 5.44 ms、范围 5.23–6.34 ms**，38 次合计约 **0.212 s**。从该 scorer 入口至结果发布的计时为 **3.103 s**，包括资源/张量校验和文件 I/O，不包括 timing 文件写入和进程退出。调用计时是完整 `fingerprintPrepared` await 延迟；若发生 GPU 降级可能包含重加载/自检，本次事件日志没有降级。计时重复的全部向量字节和逐例结果与原准确评分完全一致，没有再次读取真实照片。

这是当前可用原始资源的短时取图观测，没有证明这些资产为 iCloud-only，不能把毫秒级热读取外推为云端下载或十万张建库耗时。Source 在已授权网络目录上读取，SHA 是这次只读审计额外 I/O，不新增产品级全文哈希。表中 Source 解码项包含共同包装器的元数据读取和预处理，并非纯 ImageIO kernel 耗时。正式临时写入发生于 Photos 表示初建或重建，日常已有向量查询不重复写原片；本次临时写入字节不等于系统全部缓存/网络/SSD 物理写入。

直接启动签名可执行文件的首个尝试因 TCC 归属到 Codex 而被系统拒绝，实际 exit 1、零图片读取，失败证据保留。随后用正常 LaunchServices 启动同一签名应用，正常 Photos/网络卷授权均收到；19/19 捕获。RunningBoard 记录该原生进程由 launchd 正常结束 `(0,0,0)`；这不是仅凭 `open -W` 的退出码判断。离线评分为实际可执行进程 exit 0。
