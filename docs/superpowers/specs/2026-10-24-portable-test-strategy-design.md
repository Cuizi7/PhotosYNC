## 1. 范围与原则

- 沿用 [运行时契约](../../specs/2026-09-18-runtime-state-and-recovery.md)、[完整 Live Photo 设计](2026-10-21-native-live-photo-completion-design.md)、[任务状态与 hover 设计](2026-10-24-beta8-task-state-hover-design.md)及 [发布验收契约](../../../Design/Validation.md)。不通过改预期、减规模、放宽去重或提交守卫来通过测试。
- 在实际 `SyncRuntime → AdvancedRuntimeGraph → coordinator/engine → SyncStore` 上测试，只替换系统 I/O、时钟和外部回调。另用实际 `PhotoKitGateway` 加受控 lifecycle/requester 检验适配器，避免所有 fake 都“立即成功”。
- 默认测试仅使用仓库素材、生成数据和 UUID 临时目录，不读取个人 Photos、生产 SQLite、历史生产副本或真实来源路径。真实系统测试单独列出，不由默认命令隐式开启。
- 每个已报告缺陷形成固定场景：触发条件、可观察结果、旧行为失败证据、修复后通过证据。测试数量、编译成功和“生成了截图”不能代替这些结果。
- 不新建通用测试平台。扩展已有 XCTest、Python unittest、GUIQA 和验收脚本；作者串行实施，验证与评审按风险分工。

## 3. 测试分层与时间预算

beta8 同一归档的阶段墙钟记录如下。参考环境为 macOS 27.0.1、arm64、Xcode 27.1、Swift 6.4；不将其视为所有机器的速度保证。

| 阶段 | 实测时间 |
| --- | ---: |
| Debug build-for-testing | 68.6 秒 |
| 完整 XCTest 进程 | 180.6 秒 |
| Tools | 169.5 秒 |
| 优化规模测试宿主构建 | 70.3 秒 |
| 100k / 150k / 200k / 200k + 100k 历史 | 79.6 / 94.3 / 120.8 / 206.8 秒 |
| 两种续体回归 | 71.4 / 71.2 秒 |
| 资源和素材校验 | 约 0.8 秒 |

四档阶段合计 **18.9 分钟**，不包含正常 Universal Release 构建、原生 GUI 和 DMG。普通 `release` 档按同次阶段记录扣除三个额外样本为 **约 14 分钟的估算**，不是另一次实测。证据来源为本机 beta8 `validation.json`；下表预算需要实施后在本机全新 checkout 重新测量并提交脱敏汇总；第二台机器为补充验证。

| 层次 | 使用时机及内容 | 目标墙钟 | 硬上限 |
| --- | --- | --- | --- |
| `focus` | 每次编辑：显式选中的相关测试、固定缺陷场景；不出具完整验收结论 | 热构建 1–3 分钟，冷构建不超过 5 分钟 | 8 分钟 |
| canonical `release` | 普通非性能改动：完整 XCTest/Tools、实际模型、两种续体、200k + 100k 历史 | 15–18 分钟 | 25 分钟 |
| canonical `full` | 本轮启动/索引修复，以及索引、SQLite、资源或性能边界变动：上述全部加原四档 | 20–24 分钟 | 35 分钟 |
| 原生 UI | UI 变动的集成与发布：本节第 6 部分的六条真实窗口流程、两种外观 | 3–5 分钟，复用本轮构建输入 | 8 分钟 |
| 包装及核验 | 同一归档的正常 Universal Release、签名、DMG、校验值 | 2–4 分钟 | 6 分钟 |
| 单次完整交付 | 普通档加 UI/包装，或 full 档加 UI/包装 | 约 20–25 / 25–30 分钟 | 35 / 40 分钟总截止时间 |

预算规则：

1. 硬上限包含子进程；任何超时均终止本次拥有的进程组，保存阶段、事件轨迹和未完成项，返回非零。不终止生产 App，不跳过失败项，不自动重跑到绿。总截止时间优先于各阶段独立上限。
2. 环境准备另计：已有 Xcode 的新机器，依赖/LFS 下载尝试最多 10 分钟；失败可显式续办。Xcode 安装不是测试脚本负责的工作，不把下载耗时藏进测试计时。
3. 调度、退避、600 秒资源期限和通知交错使用虚拟时钟、明确门闩及事件；不真的 sleep 600 秒。真实取消/物理结束契约仍由受控 requester 检验。
4. 保留现有最大混合档的 60 秒空闲/RSS 恢复检查和已有性能阈值。原代码只有该档进行这项检查，不给其他档新增等待。本轮不通过虚拟时间替代真实资源测量。
5. 新增完整路径及序列测试总执行增量目标不超过 90 秒（不含构建）；固定 20 个种子、每个最多 40 个合法事件。失败保留原始种子/序列；最小化重放是显式诊断命令，最多再用 30 秒。
6. 同一归档内共用确定相同的编译输入；Debug、优化测试宿主、正常发行包各有用途，不能互相冒充。独立只读评审、证据核对不重复跑全套。最终包装仍在 exact archive 完整验收一次，不跨提交复用“通过”记录。
7. 慢机器超过目标但未超过硬上限时记录性能差异；超过上限就是未完成。不得自动降低规模、放宽 2 秒/4 GiB 等现有产品性能门槛或把平台差异当成功。

## 4. 行为覆盖矩阵

保留已有覆盖，每行新增或关联至少一个完整用户场景。输入差异参数化；不做所有维度的笛卡尔积。高风险三方交错显式列出，不指望随机测试碰中。

| ID | 场景与输入 | 必须证明的结果 |
| --- | --- | --- |
| R01 | 空库、持久索引已完成、历史任务未完成；新 runtime/store/gateway 重开同一测试库 | 首次历史识别断点继续；已完成任务不重新全量识别；成功历史和既有指纹保留 |
| R02 | 重启后历史 token 有效/失效/不可用；图库上下文不明；候选加载被门闩阻塞 | 记录真正开始来源枚举和允许提交的两个不同事件；安全的枚举不被不相关云端工作拖住，提交等待必要核实；不能仅用 `scan_run` 已插入判定开始同步 |
| R03 | 无变化、单项变化、未知范围变化；通知发生在 snapshot 前/中/后 | 完整覆盖证据才复用；未核实项不能参与跳过判定；同一有效 generation 的物理全量加载不随每个 Live Photo 项重复 |
| R04 | 普通扫描、视觉索引、Live Photo 连续 16 项切片并存 | 健康队列均推进，切片让出后自动继续；无到期项时不忙循环；已有任务不因切片结束闪退 |
| R05 | 根离线、子目录失败、同目录后到另一半、兄弟目录正常 | 目录直属枚举完成才放行该目录；故障隔离；根恢复有新鲜证据；来源只读 |
| R06 | HEIC/JPEG 与 MOV 配对、仅照片/仅视频、另一半后到、历史单项与已完整目标 | 按精确身份补齐；缺半仍可普通导入；完整目标验证前不删旧项；重复运行不重复创建 |
| R07 | 普通视频 9.999/10/10.001 秒、未知时长；明确 Live Photo 标识；损坏媒体/缺标识 | 严格大于 10 秒且无明确身份的普通视频跳过识别，但正常导入；不能将损坏支持格式当缺标识 |
| R08 | 创建/清理意图落库、placeholder、成功回调、结果落库、验证、清理各边界重启 | 一个实际提交槽；未知结果先核对，不能再次提交；晚成功保留；成功历史不被目标消失清空 |
| R09 | 旧 blocked/retry 与同组新 verified 目标并存，期限在过去；受保护旧项保留 | 被替代操作不造成永久“等待恢复”；正常保留/跳过不产生警告；真正未知创建/删除仍阻断 |
| R10 | 读失败、首字节延迟、完成回调延迟、通知分类积压、取消后物理请求未结束 | 明确归因；预算与文件所有权保留至物理结束；完成字节可复用，目标变化才失效，不因无关通知反复下载 |
| R11 | 内存各档、升/降档、固定超限、临时占用、磁盘余量不足、模型恢复 | 默认 2 GiB；高预算重开受限项一次；物理持有者不越限；健康项继续；LP身份识别固定超限正常跳过，用户可调预算的视觉索引受限按其自身契约提示，两者不能混为一类 |
| R12 | 暂停/恢复、权限撤回/恢复、停用/移除来源发生在每个关键 await 前后 | 停止新提交但结算已发出的请求；旧续体不能清除新问题或重新开放准入 |
| R13 | 所支持历史 schema、迁移失败、未来 schema、写失败与汇总读取失败 | 事务化、不删旧库；成功/未知状态保留；数据库阻断与显示陈旧统计分别表达并能恢复 |
| R14 | 已批准 33 例实际模型、无元数据、冲突元数据、改名、编辑/压缩/尺寸变体 | 原冻结内容与动作预期不变；实际模型执行；不以素材数量宣称真实人群误判率 |
| R15 | 日志各阶段、零进展、恢复与重复故障 | 队列等待/读取/分类/入库/收尾分开；有分母和真实间隔；不把 checked 净增当下载速度；不输出私人标识 |
| R16 | 打包输入变更、缺资源/LFS、零测试、缺阶段、超时、旧报告、签名/架构异常 | 硬失败且不留下成功发行目录；同一 source/fixture/model/环境身份贯穿证据 |

**必须固定的交错组合：** 重启 + 历史未知提交 + 恢复；全量候选加载 + LP 16 项 worker + 来源枚举；资源完成 + 无关通知 + 暂停；旧 attempt + 新 verified 目标 + 过期 retry；目录恢复 + 旧失败续体；高内存档变更 + 旧读取晚失败；数据库错误 + 统计错误 + Settings 重开。

每次状态变更后检查四个核心不变量：未知写入没有第二次提交；终态工作没有幽灵待办；真正等待有阻断证据或下一触发条件；恢复后健康工作能够继续。随机事件只能排列这些合法输入，不能复制一份产品状态机当“独立真值”。

## 5. 冷启动与速度的验收方式

测试构造 1,000 个表示、200 条成功历史、40 个待识别项；旧历史由真实 store/coordinator 写入测试库。随后销毁第一轮对象，至少一组用例真正结束 QA 子进程并重新启动；保留同一隔离数据库和 fake 系统提交日志，清空内存缓存/observer。冷启动必须走实际 `bootstrap()`，保留配置检查、日志/数据库打开和图构造；在构造任何生产路径或系统 Photos 适配器之前完成依赖注入。`prepareInjectedRuntime()` 的较小测试保留，但不充当完整启动证据。另保留现有最大规模档。

记录以下单调时钟事件，并区分“含人为阻塞的端到端耗时”与“依赖已释放后的处理耗时”：

- `runtime_started`、`history_checked`、`candidate_load_begin/end`；
- `first_source_entry`（directory reader 真正交付首项）；
- `first_submit_admitted`、`first_submit_completed`；
- 每类 worker 的入队/开始/落库、物理读次数、模型调用次数、队列最长空档。

无变化且连续性可证明时，既有指纹不重算；每个固定 generation 的底层候选全加载最多一次，缓存 API 被调用多次不等于重复加载。没有连续性时允许必要的有界重核对，但不删除已有指纹、不绕过内容守卫、不将全库原片分析当来源枚举前提。

在固定合成负载下，依赖已就绪到首个来源项/首项合法提交的各次延迟目标不超过 2 秒；另用门闩证明来源枚举不依赖不相关的历史原片完成。该目标不代表承诺真实 iCloud 冷启动在 2 秒内完成。既有优化规模档的 2 秒 p95 / 4 GiB 等门槛不变。回归必须同时断言正确结果、调用量和有界推进，不能只断言 UI 离开“正在准备”。

## 6. UI：真实窗口优先覆盖高风险流程

既有离屏矩阵用于文案、布局、1×/2×和尺寸检查，继续保留；新增以下六条流程，浅/深各一次。使用实际 `PhotoSyncApp` 的 `MenuBarExtra` 和 `Settings` scene；macOS 13 单独走产品已有的设置窗口回退。GUIQA 的额外 `WindowGroup` 不能替代 Settings 验收。

| ID | 动态流程 | 关键验收 |
| --- | --- | --- |
| U01 | 准备 → 同步 → 完成；一项/两项任务；已知/未知总量 | 每任务一行小字和自己的等宽纯色进度条；顺序稳定；归属和数量正确 |
| U02 | 正常 → 数据库阻断 + 统计读取失败 → 两者分别恢复 | 两条红字均正立、完整、顺序正确；准确文案；恢复后无残留 |
| U03 | 运行 → 等待 → 暂停 → 恢复；worker 多片推进 | 等待/暂停停止动画，排队任务不闪现消失；正常跳过不产生任务/感叹号/hover |
| U04 | 打开每种任务的 hover，再退出 | 标题和一个正文段落；无第三行、滚动或另一任务内容；菜单与设置语义一致 |
| U05 | 两条错误状态下选择文字、调整窗口、滚动、关闭再打开；重复 5 次 | 实际合成像素无翻转、遮挡或裁切；关键控件可达；不靠修改产品文案绕过 |
| U06 | 默认内存档 → 调整 → QA 重启；无来源/有来源的按钮状态 | 2 GiB 默认与峰值用途说明正确、设置持久化；仅操作 fake runtime，系统开关不产生副作用 |

截图必须来自该 QA 进程的真实 WindowServer 窗口；记录窗口类别、PID、场景、逻辑/像素尺寸、backing scale、源码/产物哈希。通过应用自己的动作或目标窗口 AX 操作，不发全局 ⌘W/⌘Q、不关用户窗口。

方向检查分三层：文案与布局断言；像素方向检查（正立文字基准与倒置负对照）；逐张目视审阅 U02/U05 的关键帧及所有新差异。OCR 可能自动纠正倒字，**OCR 识别到文字不算方向通过**。把一张自制文本图上下翻转/旋转 180°，检查器必须拒绝；截图检查器自身也要回归。不承诺跨 macOS 像素完全相同，使用文字区域与几何断言；基准更新必须人工解释差异。

原生 GUI 需要登录桌面及正常授予测试执行器的相关权限。缺 WindowServer、屏幕捕捉/AX 权限、窗口被锁屏影响时，快速报告 `blocked_environment`，不降级成离屏通过。实际 1×/2×在有对应显示环境的机器核验；不得把离屏缩放写成真实显示倍率实测。

原生阶段放在本轮 Debug build 后、规模测试前。捕捉及自动断言通过后输出本次图集、待审清单与 `pending_review`，最多等待 **180 秒**由审阅者（开发者或实际查看图片的代理）填写逐帧结果。用仓库脚本写入 `ui-review.json`，绑定本次 run ID、source/binary/场景身份与每张必需 PNG 哈希；缺项、旧记录、拒绝或过期均失败。等待包含在原生8分钟和总体截止内，通过后同一归档进程继续余下检查，不另起一轮全量验收。不把自动填满“通过”当作目视审阅；无人值守 CI 可跑无UI功能档，但不能据此放行要求native的UI发布。

## 7. 可提交素材、依赖和复现

依赖清单区分 macOS 自带工具、Xcode/SDK、Python 虚拟环境、Git LFS 和脚本当前使用的 `rg`。`--prepare` 在同一10分钟截止内准备虚拟环境并显式取得/水合当前提交所需的LFS对象，拒绝覆盖修改过的模型文件；其余缓存只写测试work根。不改全局 Python、Git 配置、照片权限、系统图库或生产偏好。Xcode 和 macOS 由机器预先安装，无法作为仓库测试依赖一起打包；精确参考版本及最低能力检查必须写入环境报告。

`CI=true` 不再无条件拒绝，但也不靠取消环境变量绕过：先验证固定素材完整性、项目使用授权清单和模型身份，仅允许仓库登记的测试集进入 canonical。未知外部数据路径、缺授权或 hash 不符均失败。既有公开授权限定为本项目测试，不重新标成 CC0。这里不新增公共 runner、云服务或自动上传日志；相同命令具备接入 CI 的条件。

实施后统一命令：

```sh
# 第一次：在已经安装 Xcode/Python/Git LFS 的新 checkout 中显式准备依赖。
python3 scripts/test-environment.py --prepare --root "$PWD/work/test-environment"

# 日常相关回归；focused 证据不能交给发布门槛冒充全量。
work/test-environment/venv/bin/python scripts/run-focused-tests.py \
  --suite startup --output-dir "$PWD/work/focus-startup" --derived-data "$PWD/work/focus-startup-derived"

# 完整验收继续使用唯一入口；本轮索引/启动边界使用 full。
work/test-environment/venv/bin/python scripts/validate.py --scale-profile full \
  --ui-profile native --output-dir "$PWD/work/validation-full" --derived-data "$PWD/work/validation-full-derived"

# 最终发布由同一归档重跑完整门槛；不是先把上面整套再机械跑一遍。
PATH="$PWD/work/test-environment/venv/bin:$PATH" \
  scripts/package-release.sh --scale-profile full --ui-profile native
```

新增脚本及 `--ui-profile` 尚未实现；实施计划给出落点。证据目录必须新建，例子不可反复覆盖同名目录。准备完成后，默认验收不需要网络、Apple ID、NAS、开发者证书或个人图库；模型转换、私有样本复放和真实 Photos 系统验证不进入默认路径。

native命令会在终端输出本次图集与逐帧判定模板。审阅者查看真实PNG后填写模板，在另一个终端运行以下命令提交本轮审阅；它只核验并记录审阅，不代替审阅者看图：

```sh
work/test-environment/venv/bin/python Tests/UIReview/run-native-scenes.py \
  --record-review /path/from/current-run/review-decisions.json \
```

可复现交付验收：本轮在本机全新 clone、全新虚拟环境和 DerivedData 中执行最终 canonical，不拷贝原 work/、用户偏好或生产数据库。它证明干净环境可重复执行，不写成第二台机器实测。第二台 Mac 为补充验证，不要求用户为本轮准备额外硬件；涉及旧系统、Intel 或系统兼容边界变化时再安排对应实机。报告源码/素材/模型 hash、OS/Xcode/Swift/Python/架构、profile、时长与未测边界。

## 8. 不能由模拟替代的系统验证

- 改变 PhotoKit 实际调用/原资源读取、授权、平台边界时，在独立测试账号系统图库中用仓库自制素材验证真实创建、重开、播放/声音和定向清理；不自动切换生产图库或开关 iCloud。授权与准备独立列出。
- 真实 iCloud 首字节/系统缓存行为、SMB 断连及系统休眠，用有条件的系统检查记录；默认测试用 fault injection 覆盖逻辑，不声称模拟已证明 Apple 云端速度。
- 可选真实图库只读性能探针最多 5 分钟，记录候选枚举/等待/读资源的匿名聚合；独立测试状态，所有写入入口拒绝。它不是默认合并条件，也不能替代可提交的复现案例。
- 平台矩阵：当前 macOS + arm64 每次集成；macOS 13 回退窗口、14+ Settings scene、Intel 的独立 smoke 在首次接入及相关边界变化时补测。旧系统使用可部署的独立 QA 宿主，不假定当前 XCTest runner 能运行。未测的平台逐项标明，不能用 Universal 架构检查替代实机执行。

## 9. 放行与报告

证据包含 source/model/fixture identity、每条场景的预期和实际、执行次数、状态轨迹、物理调用量、阶段耗时、GUI 捕捉方式、失败/跳过原因及逐帧审阅清单。分别汇报功能、性能、原生 GUI、真实 Photos、平台与打包结果。

新增必须场景缺失、超时、零测试、错误 profile、无语义原因的 skip、GUI 像素未取得，均不通过对应门槛。原有两个条件 skip（独立规模入口、可选私有向量重放）使用精确测试 ID 及原因白名单；另一个测试被跳过不能占用它们的名额。

发布前 reviewer 先从用户行为契约提出反例，再看实现与测试，重点检查冷启动、安全准入和真实 Settings 路径。同一最终快照只做一次完整集成评审；修复新增问题后复核受影响部分。当前两个缺陷至少各有旧行为失败与新行为通过证据；若只能重现其中一层，明确留下未覆盖边界，不能宣布问题全部解决。
