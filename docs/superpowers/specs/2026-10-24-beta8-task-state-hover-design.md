# Beta8：正常跳过、索引维护与简短说明

用户已审核多场景原型，并要求删除所有 hover 第三行；2026-10-24 授权写 plan、串行实现、合并并发布新 beta。

## 行为

- Live Photo **身份识别**因固定编码资源上限无法继续时，持久化为正常跳过，保留未能识别的证据；不伪装成没有配对标识，不算识别成功。跳过计入任务已处理数量，不计入未解决、重试或需处理；同一资源不因重启或立即扫描重读，资源变化后按正常增量逻辑重新识别。
- 升级将旧版明确记录了资源上限的识别搁置项事务化迁为跳过，不重跑全库清点，不访问媒体。普通读取失败、来源问题、解码内存上限和未知提交不在转换范围内。
- 正常跳过不生成任务警告或专门 hover；其余工作结束后，任务退出任务区。来源离线等独立问题保持展示。
- 已识别配对的创建、验证、替代清理及源文件预留遵守现有契约。跳过识别不能作为“图库里不存在完整 Live Photo”的证据；已有原生候选的保守准入、未知提交及未验证目标保护保持不变。
- 每 30 分钟的例行索引维护先做轻量连续性校验。仅在当前实例已完成索引、监听持续有效、上下文与代次相同、没有待处理变化、现有发布仍有效时，省略全库 catalog 遍历；保持已知总量和可用发布，不显示新的索引任务。启动、强制扫描、覆盖缺口或证明不足仍执行原有核对。
- 每个任务 hover 统一为 **标题 + 一句正文**，不带小节标题或第二段，不滚动。任务保持一行小字及等宽 5pt 纯色进度条；暂停、等待和数字更新不无故销毁说明入口。正常完成无任务提示。

## 准确文案

| 场景 | 标题 | 唯一正文 |
| --- | --- | --- |
| 视觉分析（总量已知/未知） | 视觉索引 | 分析照片内容，帮助避免重复导入。 |
| 配对识别 | Live Photo 配对 | 识别照片与视频的配对关系，找到另一半后自动补齐。 |
| 补齐/验证 | Live Photo 配对 | 正在补齐包含动态画面和声音的 Live Photo。 |
| 自动读取等待 | Live Photo 等待恢复 | 部分原文件暂时无法读取，稍后自动重试。 |
| 暂停 | 已暂停 | 已完成的结果会保留。 |
| 暂停收尾 | 正在结束当前操作 | 已提交给“照片”的操作会继续收尾，之后暂停。 |
| 未确认保存 | 等待“照片”确认 | 保存结果尚未确认，新的保存已暂停。 |
| 视觉内存上限 | 需要提高内存上限 | N 张照片超出图像处理内存上限。 |
| 照片授权 | 需要照片访问权限 | 请打开设置，点击“授权访问照片”。 |
| 来源不可用 | 来源目录不可用 | 请检查来源磁盘或网络连接。 |

任务外已有的授权/来源操作入口保持原位置；复杂的来源文件问题详情不在本次任务 hover 重构范围。其他真实失败用一条已有用户可读摘要，不向用户暴露系统错误原文。

## 取舍与验证

采用持久化正常结果、连续监听证明及随状态变化的短说明。单纯隐藏错误不能结束持久待办；只改索引标题仍会每半小时遍历全库并撤下可用发布；固定帮助长文已被用户否决。

使用临时库与 fake Photos 验证迁移、重启、手动扫描、变化后重排和监听/授权竞争；用实际 SwiftUI 视图与假数据核对菜单、设置及说明的浅深色渲染。最终归档执行 full profile，评审后本地 squash 到 main 并发布 0.3.0 beta8（build 25）。不操作生产数据库、图库、来源、安装或运行应用，不执行远端推送/发布。
