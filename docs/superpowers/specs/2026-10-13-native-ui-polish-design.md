## 3. 进度：只使用同一份持久汇总

输入为一个 `EngineSnapshot.summary: SyncStatusSummary?` 的原子快照。不查询数据库、不重数来源文件，不从文案反解析数字。

```text
imported   = summary.imported
skipped    = summary.skipped
incomplete = summary.pending + summary.importing + summary.retryPending
processed  = imported + skipped
known      = processed + incomplete
```

`known` 表示当前启用且未移除来源中已登记的文件记录，包含此前扫描；不是此次目录扫描的最终总数，也不是 Photos 图库总张数。`retainedImported` 不进入分母或色段，仅保留在详情。不能把 `latestScan.checkedCandidates`、`latestScan.newlyImported` 再加进这些数字。读失败但尚未落库的文件不在分母中，现有问题提示必须继续可见。

| 色段 | 数量与比例 | 颜色 |
| --- | --- | --- |
| 已导入 | `imported / known` | `Color.accentColor`，与图库分析的 `.tint(.accentColor)` 相同；默认系统主蓝色 |
| 已跳过 | `skipped / known` | `Color(nsColor: .secondaryLabelColor)`，随明暗模式适配的深灰 |
| 未完成 | `incomplete / known` | `Color(nsColor: .quaternaryLabelColor)`，浅灰轨道 |

从左到右相接填充，同一外层圆角轨道，建议高 6pt；不为零数量绘制最小假色段，不显示摆动色块、预估剩余时间或“全程百分比”。宽度精确按数量分配，不把数字变化动画成单调递增。新发现文件可以让分母增加、比例回退。

主文案为 `已处理 P / 已发现 K`（十进制完整计数，不使用 K/M 缩写），下方有“已导入 / 已跳过 / 未完成”文字图例，辅助功能同时说明各段数量。六位数在 292pt 内容宽度内完整显示；不得靠缩小系统字号解决。

边界：

- `summary == nil`：无比例/无假零，使用现有 `model.counters` 的读取中或不可用文案。
- `known == 0`：显示“已发现 0 个文件”和空轨道，不除零，不解释为 100%。没有启用来源时不画同步进度，保留状态/权限引导及详情入口。
- 有旧 summary 且 `summaryError != nil`：保留旧值并在主界面明确显示“统计暂未更新”；错误摘要仍用现有 model。
- 所有未完成状态都占浅灰；包括提交结果尚未确认、明确待重试，不能当作完成。
- 满条不能覆盖 `model.statusDescription`。未挂载、未确认提交、坏文件、暂停等仍按既有优先级显示，不从 `processed == known` 推导 `.completed`。

例：`120 imported + 30 skipped + 49 pending + 1 importing + 0 retryPending` → `150/200`，三段为 60% / 15% / 25%。即使另有 500 条退役历史或本轮检查 86/新增 24，仍然是 `150/200`。

## 4. 菜单信息层级和详情

2026-10-15 本轮必要展示变更见[来源诊断与图库分析详情设计](2026-10-15-diagnostics-and-analysis-details-design.md)：以完整诊断单一摘要、共享原生浮层和同快照分析组替代本节对应旧约定，其余边界不变。

顺序：状态标题与活动指示 → 现有全局阻断/恢复提示 → 当前阶段进度 → 来源两行列表 → 下次扫描 → 固定操作区。

- 标题和图标直接消费 `model.statusDescription`、`model.status.symbol`，不新写业务状态优先级。
- `model.analysis != nil` 时前景只显示图库分析进度，不同时画源文件进度。保留 totalsKnown 的确定/不确定表现、iCloud 等待文案、暂停进度及 ready 后隐藏规则；同步记录仍可在详情中查看。
- 没有分析区且有启用来源时显示上述同步分段条。移除常驻的 `model.counters` + `model.scanDescription` 两段重复统计，完整数据转入详情。
- 来源仍采用当前筛选规则：只显示启用且有问题或阶段的来源；不排序、不增加逐文件错误列表。
- 权限缺失、提交未知、检查点失败、统计过期等提示及恢复建议仍直接可见；通知/日志警告也不静默丢弃。来源行的未解决文件错误数量仍可见。长摘要可以受限，但完整人话和 raw detail 必须可获取。
- `nextScan` 存在且 `activeWork == false` 时显示“下次扫描：时间”，不自行估计扫描时刻。
- 主操作一行“立即扫描 / 暂停同步（或继续同步）”；次操作一行“设置 / 退出 PhotosYNC”。只有“设置”去掉省略号，保留“添加来源目录…”等原有名称。

2026-10-13 人工验收反馈修订：主操作使用等宽、等高的原生有边框按钮，形成左右两列；下方水平分隔后，次操作使用纯文字按钮，两列之间有短竖分隔线。不得以各自内容宽度的小按钮加 Spacer 代替原型的列秩序。原生控件可以表达此结构。分析区删除重复的“图库分析”小标题，将现有“已分析 X / Y 张”（未知总数时保留原文案）和详情入口并排放在进度条上方，解释和等待提示在条下；详情入口紧邻摘要文字。两组详情均按左侧名称、右侧值逐行对齐，“本次扫描”不得拼成一段长句；阶段、可选失败/来源等待和已有时间仍保留。

`ⓘ` 为有辅助功能名称“查看同步详情”的原生 Button，位于进度摘要旁；分析/无来源/无统计时仍可从状态区域找到入口。

详情用原生 popover，包含“已发现的文件”与“本次扫描”两组。第一组逐项显示 imported/skipped/pending/importing/retryPending，以及存在时的 retainedImported/summaryError；第二组复用现有扫描呈现口径，含候选检查、新增导入、文件失败、来源等待、阶段、已有时间。footer：“统计当前启用来源的记录，包含此前扫描。总量随新文件发现而增加。”不把两组数相加，不把跳过解释成精确重复。

hover 在 200ms 后打开，移出按钮和 popover 的联合区域后 200ms 关闭，进入任一处取消关闭；点击或键盘 Space/Return 打开并保持，Escape/点击外部关闭，关闭后恢复到触发按钮的焦点。窗口消失取消延迟任务。局部交互状态属于视图，不写 model/store；不要造成移动到详情时立刻消失的闪烁。

## 5. 两行来源路径（菜单、设置、demo 共用）

2026-10-15 本轮必要展示变更见[来源诊断与图库分析详情设计](2026-10-15-diagnostics-and-analysis-details-design.md)：以完整诊断单一摘要、共享原生浮层和同快照分析组替代本节对应旧约定，其余边界不变。

第一行是同一基线上的一条完整路径：父级前缀 `.caption + .secondary`，末级名称 `.caption + .primary`，整行字号和字重一致，仅通过颜色突出末级名称；浅色末级深色，深色末级为正常浅色主文字，不能用蓝色链接色。`.lineLimit(1)`，整体从**开头**省略，尽量完整保留末级文件夹名；末级自身也超长时同样按头部省略，保持可见后缀，不压缩字体。

路径 hover 是完整 `URL.path`，辅助功能也读完整路径。不主动规范化路径、不访问文件系统、不改变来源身份；仅处理显示，根路径 `/` 也不出现空末级名称。

第二行显示现有状态摘要，`.caption + .secondary`、单行尾部省略，完整状态与系统 detail 保留在状态 hover/辅助功能中。有未解决文件数量时在同一行保留紧凑的“读取失败 N 个”提示，状态文字先省略，不能加第三行或丢掉数量。文件夹图标在左，设置的启用/停用、移除按钮在右。

完整路径 hover 与状态 hover 是两个独立目标，不能让只覆盖状态的 tooltip 取代完整路径；设置按钮空间从路径行可用宽度中扣除。

## 6. 设置布局

顶部：状态、边界说明、现有阻断/恢复提示；未授权时把现有授权说明和授权按钮放在附近，同一个授权问题不在底部重复显示。其他独立错误、notificationWarning 和关闭提示动作均保留，去重不能靠修改状态或丢弃其他问题实现。

来源标题和添加按钮保持在列表之外，只有来源列表滚动。常态列表最多 280pt，短列表收缩；根据其他固定区域的实测高度进一步缩小，以满足 680pt 上限。列表下方的通知、登录启动、诊断入口保持可达。若长警告/辅助功能字号使静态区域本身放不下，外层允许受限滚动作为退路，不裁掉控件；普通 30 来源场景不能退化回整个窗口长滚动。

继续使用现有设置内容高度回调，防止布局测量反馈循环。版本信息放到底部弱化。设置不增加图库分析页、同步进度仪表盘或新导航。

## 7. 实现边界和验证

局部拆分仅为共享路径显示、进度/详情控件两项职责服务。不建设新的 ViewModel、业务状态机、设计系统或兼容层。新 App 文件只加入 app 与 hostless tests 编译目标，不能加入 Core。

自动覆盖：进度计算与未知/过期边界；不完整状态/退役记录；完整率不改全局标题；短/长/Unicode/根路径；明暗模式；来源错误数量；0/1/30 来源布局；固定设置区和原操作映射。继承原 `AppModelTests`、`SyncStatusPresentationTests`；最终执行项目规定的完整 `scripts/validate.py`，不能用 selected tests 宣告完整验收。
