# PhotosYNC 0.2.3 index diagnostics, retry timing and reader backpressure

Approved scope: the human authorized implementation and release through the coordinating chat on 2026-10-16. This spec refines that approved scope; no new approval pause is required. Baseline main/v0.2.2 is 1d91d76618b47570cdf9b2bd509b3b24d5a329de.

## Outcome and constraints

Ship 0.2.3 stable/build 11 with bounded causal diagnostics and correct retry/backpressure scheduling. Do not claim repeated history invalidation is fixed. Preserve schema v8, persistent checkpoint/observer coverage, conservative history invalidation, same-revision edit detection, import success history, matching/model/threshold/media/permission rules, and actual physical ownership. No production App/Photos/database/source/network/settings access. Tests use fake Photos, self-made fixtures and UUID temporary databases. No helper process, new telemetry database or durable queue schema. Existing artifacts and worktrees are retained. macOS 13 minimum and Universal build remain; macOS13/Intel hardware testing is excluded by user direction.

## Bounded causal diagnostics

Use one small, shared per-runtime diagnostic context with a fresh random run identifier and secret; anonymous asset/descriptor/issuance handles remain stable across reconciliations in that runtime. No raw token, new raw asset IDs, paths, images or EXIF. Keep at most 8 sticky sample asset keys per run; detailed lifecycle events apply only to those samples, with a fixed per-operation event cap. Aggregate counts for all other assets. Existing high-volume index diagnostic call sites must not negate bounds: coalesce neutral notification/classification events in bounded windows and report suppressed counts. Never change decisions or silently discard error/state transitions to throttle logs. No new per-asset persistent state or all-library vector materialization for logging.

Correlate replay/live source and category, reconcile/run/reason, history range handles and local generations, invalidation reason/count, actual ready-to-pending counts, retained-ready, task descriptor/issuance, request/timeout/cancel/terminal/drain/lease release, failureAt/deadline and slice reason. Record unknown as unknown. No token equality or new coverage claims. Diagnostics must be nonthrowing and outside database/PhotoKit lock-held waits. A small helper file and Xcode target membership are allowed.

## Timing and bounded fair slices

Inject wall and monotonic clock closures with production defaults. Preserve existing processDueWork(now:) source compatibility for tests/callers; make its role the slice eligibility cutoff, not the failure timestamp. Capture one wall failureTime at the actual failure handling point and reuse it for durable deadline/logging. Backoff stays 5/15/30/60 seconds, existing model delay stays 60.

One slice freezes due cutoff; at most 16 task attempts and a 1 second monotonic admission budget. Time budget means do not start another task after the current owned work ends, never kill work at the boundary. One issuance is attempted at most once per slice. Use a bounded rotating key cursor/keyset selection with wrap to ensure both new work and due retries advance across slices; no new persistent scheduling table. Keep consumer processing guard, actor revalidation after awaits, pause/context/generation/issuance fences. Return to existing runtime tick for continuation and progress; no unbounded self-spawn loops.

## Reader admission and global deferral

Prefer a level-triggered async admission snapshot queried by the existing periodic runtime tick rather than a new event subscription. This makes terminal-before-query safe without subscriber races. The snapshot must include actual active ownership and budget availability; an empty active dictionary is insufficient while cleanup or a returned image lease is still outstanding. Revalidate after awaits. Default protocol implementation permits existing fake gateways without real resources; controlled fakes explicitly model busy/draining/stalled.

Pre-admission busy is global deferral: no sibling task failure/retry increment/vector removal, stop the slice. A logical timeout retains its physical owner and budget, records at most one timeout for its own issuance, enters draining and stops the slice; no per-sibling failures. Reader/budget deferral does not become an isolatable damaged-image failure. Preserve exact per-item terminal bad-image isolation, -1009, model and store error rules. After real drain and budget cleanup, a later tick automatically resumes durable work. Successful returned leases continue blocking capacity until their real consumer finishes. Duplicated terminal/drain must be idempotent. After 60 monotonic seconds awaiting physical completion, show one aggregate stalled wait and retain the owner; never invent termination or replace a reader to bypass it. No guarantee of automatic recovery if the system never ends the request. State transitions are coalesced, UI remains responsive; any changed visible waiting copy must have synthetic native-host coverage.
