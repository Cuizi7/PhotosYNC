# PhotosYNC 0.2.0 高级照片判重设计

日期：2026-09-28；最近更新：2026-10-06
状态：用户明确选定初始阈值 0.98，研究阶段按该决策收尾；当前 33 例回归通过，44 例历史底本保留。未开展独立校准/封存统计验收；P1–P8 已实施，P9 固定资源及真实 33 例已验证。用户已授权 SQLite 查询和 Photos 按变化更新索引，实施后补最终验收/审阅；性能目标没有豁免。
设计基线：`ecde48cf55e5e47dbfbf2fc614ccba7191180e8b`（0.1.0 stable）。

## 1. 目标与成功条件

导入前识别同一张照片的副本，包括改名、修改 metadata、压缩、缩小和常见格式转换。十万张级 Photos 图库应能增量维护索引，日常导入不重复读取全库图片、不逐张运行模型。

本版完全由机器决定，不增加人工确认、人工审核队列或相似照片浏览器。误跳过意味着用户照片没有导入，因此优先控制误跳过；比较成功但证据不足时导入。读取失败、索引未完成等属于未知，等待恢复，不能等同于“不是重复”。

用户已选择：SSCD Large；单模型候选检索与阈值判定；允许按需下载 iCloud 图像；首次索引就绪后才开始导入；更高分辨率副本仍导入；重新评估符合条件的旧疑似重复跳过项；持续维护 Photos 索引；同时覆盖 Photos 原始版和当前编辑版。2026-10-05 用户决定先采用 0.98 推进产品集成，停止进一步独立校准/封存研究，后续根据生产情况显式调整参数；保留生产诊断日志。这一决定替代原有研究统计通过前置，不表示原统计目标已获证明。

## 2. 范围与保留规则

- 高级内容判重用于现有支持范围内的静态照片。视频保持 0.1 的文件名与 metadata 策略，不增加视频抽帧、RAW 来源支持或 Live Photo 配对。Photos 中复合资产的可读静态照片表示可作为照片候选，不能据此判断其视频部分重复。
- 只读来源；Photos 只新增，不修改、替换、删除已有资产。仍提交来源原始 URL，`shouldMoveFile = false`，不重新编码导入文件。
- 不加入 pHash、第二个核验模型、服务端模型或独立向量数据库服务。指纹在本机生成、持久化和查询。
- 不将连拍、同场景、同人物等语义相似视为足够的重复证据。已确认的当前回归案例中，明显裁剪、明显调色、景深/虚化与明暗/对比编辑应保留为不同版本，判不重并导入；近邻街景中的车辆位置、取景变化也应判不重。2026-10-04 用户将 11 个合成信息看板用例移出当前测试范围，其旧标签保留为历史，不改成判重，也不从本次删例推导对所有文字差异的识别承诺。这些是具体案例的预期，不等于任意微小颜色或像素变化都必须判不重。
- 画面整体旋转 90° 是否构成需要保留的构图编辑尚未定案。B015、B017、B019 已移出当前回归集，先前审批不作为旋转规则的冻结依据；后续评估实际能力后再决定。正常解码时对 EXIF 方向的解释不因此省略，也不等于已决定用户主动旋转编辑的判重语义。
- 不假设单个向量分数能识别具体变换类型。运行时只使用已冻结的分数及可观测规则，测试覆盖已确认编辑与易混淆负例；旋转仅可作为未定预期的探索样本。当前采用第 7 节绑定的用户选定配置；原协议的误跳过率及分层召回统计目标尚未验证，不再作为本轮进入集成的前置。当前固定回归的内容与动作仍必须满足，实施者不得擅自删除已批准难例、改标签或临时加入第二模型掩盖限制。用户明确调整范围时应另存版本和原始理由，保留旧证据，并重新建立相应验收绑定；事后缩小范围不能冒充独立校准成功。若源文件本来就是图库当前编辑版的副本，应能匹配该表示；编辑版与原图判不重，不表示该编辑版自身的副本也要重复导入。
- 保留四种文件状态 `pending`、`importing`、`imported`、`skipped`；索引任务状态另行持久化，不新增文件审核状态。
- 成功历史不因来源停用、移除、文件变化或 Photos 删除而清空。未知 Photos 提交结果仍禁止盲目重试，同一时刻仅一个实际提交。
- 本文在静态照片判重、指纹存储和 Photos 图像读取范围替代 v1 的相应限制，其余运行时契约继续遵守 `docs/specs/2026-09-18-runtime-state-and-recovery.md`。

## 3. 判重流程与决策

### 3.1 指纹与候选

来源图片和 Photos 图片使用同一套方向、颜色、缩放、像素归一化与向量归一化处理，生成 SSCD Large 1024 维向量。模型、转换产物、预处理、向量格式和策略均带版本及校验值。本次固定为 FP32 Core ML / CPU-only、sRGB、全画面 stretch 320×320，不中心裁剪；沿用 R2 的归一化参数及已保存的 fingerprintVersion。方向/颜色/宽竖图行为和固定回归已有研究证据，不能将其外推为任意全景、变换或真实 PhotoKit 输入均已验收。

文件名、拍摄时间、设备等 metadata 用于上下文、日志与已有历史身份规则，不是静态照片内容候选的强制过滤条件。改名、时间调整、metadata 缺失不能阻止内容匹配；同名本身也不能让新策略跳过不同图片。

候选包括当前 Photos、有效本地待导入/导入中项以及保留的成功历史。向量检索后用持久化的规范化向量计算最终余弦分数，不能直接以近似索引距离作阈值决策。索引输出是相似候选，分数不是“重复概率”。

检索需要覆盖达到判重阈值的候选，不能只拿最近一张决定：必须防止最近的低分辨率版本掩盖另一个已经存在的高分辨率版本。用户于 2026-10-06 选择 SQLite 方案：同一 SQLite 读事务流式遍历全部有效候选，保留原 Float32 `vDSP_dotpr` 精确分数、全部达阈值候选和全局最近 10 条诊断；不保留全量向量堆缓存。SQLite mmap 是可回退的读优化，不是索引正确性的前提。诊断条数不能截断判定候选，本版不引入近似检索。新检索身份为 `sqlite-exact-f32-v1`，必须进入配置、policyVersion 和日志；模型与 fingerprintVersion 不变。旧 `exact-f32-v1` 是历史基线，不能冒充新后端验证。

补充验证后选择系统 SQLite + Accelerate 的单次游标扫描：用一个窄的 C/Swift 桥复用原精确评分和 Swift 同分排序，避免 sqlite-vec L2 粗筛后的二次扫描、排序与复核。此实现不依赖 sqlite-vec、不自制向量数据库或常驻缓存。每条有效候选在评分前校验 BLOB 类型、4096 字节长度、有限分量和原有单位范数容差；不命中的损坏向量也使整次查询失败，不能返回部分跳过证据。候选资格、上下文、版本、尺寸及本地修订仍由现有 SQLite 规则约束。

### 3.2 决策顺序

| 条件 | 动作 |
| --- | --- |
| 已有明确成功历史保护该来源记录 | 保留成功结果，不能因目标消失自动补导 |
| 已提交但结果未知 | 沿用恢复流程，不重新提交 |
| 来源变化、删除或读取故障 | 沿用对应安全规则，不用模型覆盖这些结论 |
| Photos 必需索引不完整、过期或当前上下文无效 | 等待更新；允许扫描准备，禁止新提交 |
| 没有达到当前阈值 0.98 的有效候选 | 导入 |
| 存在满足规则、且分辨率足以覆盖来源的候选 | 自动跳过并持久化证据 |
| 匹配候选都明显低于来源分辨率 | 导入更高分辨率版本 |
| 图片比较成功，但尺寸或其他判定依据不足 | 保守导入，并记录原因 |

分辨率按方向归一化后的原表示像素尺寸比较，绝不使用模型输入尺寸或预览图尺寸。候选长边和短边均不小于来源时，才允许它阻止更高分辨率导入。来源两边均不小于候选且至少一边更大，属于明确的分辨率升级；一大一小、无法可靠取得尺寸等不确认为覆盖。文件字节大小、JPEG 质量猜测不作为分辨率证据。

原始版和编辑版各自配对其自身尺寸。一个大尺寸原图不能自动借用另一个编辑表示的匹配分数证明该编辑图也已高清保存。多个候选中，只要一个真实匹配表示足以覆盖来源即可跳过。

本地尚未成功项作为暂时阻止重复提交的依据时，保留依赖关系，不将它伪装成成功历史；候选消失、失效或不再能提交时，依赖它的跳过项应重新判定。采用稳定的队列顺序避免两个 pending 相互引用导致都不导入。

### 3.3 历史指纹的边界

新成功导入记录保留来源指纹、表示尺寸和版本，Photos 删除后仍能作为历史证据。旧成功记录没有指纹时只沿用已经保存的历史身份保护；允许在正常授权读取范围内补齐仍可读的关联资源，但不为了补齐而扫描停用来源或要求已删除图片重新出现。资源均不可用时，不能承诺跨文件名识别这段旧历史，也不让无法补齐的历史阻断全库就绪。

## 4. Photos 索引是持续同步的本地副本

### 4.1 触发与覆盖

| 触发 | 工作 |
| --- | --- |
| 首次启用 | 枚举现有 Photos 照片，构建所需表示的指纹；完成前不开始导入 |
| 应用启动、恢复运行、图库或授权上下文变化 | 重新核对图库清单及版本，补上离线期间变化 |
| PhotoKit 变化通知 | 合并新增、改变、删除事件；尽快更新受影响资产 |
| 应用运行时每 30 分钟 | 对 Photos 做清单/metadata 对账，补偿漏通知或变化集合不可增量计算的情况 |
| 每轮导入准备及提交前 | 检查对账状态、未处理变化和索引代次；失效则重新判定 |

定时检查与现有扫描节奏合并，不叠加任务、不在休眠恢复后补跑所有过期周期。应用退出期间不引入额外后台守护进程，下次启动补齐。

完整清单对账可以遍历十万条资产的轻量信息，但不能每轮重新解码十万张图。资产标识、修改线索和资源描述用于找出变化；不能只按拍摄日期、文件数或“上次最大时间戳”找新增。PhotoKit 明确报告改变时，即使尺寸相同也要失效检查。无法确认变化范围时重做清单核对，无法证明某指纹仍有效时才重新生成。

正常增量通知必须绑定图库上下文和连续的起止 Photos 代次，只查询并更新受影响资产；新增、修改、删除合并后仍须证明变化集合完整。缺基线、代次有缺口、通知丢失/溢出、非增量变化、授权/上下文不明时退回完整对账。按 ID 查询未返回某资产不等于已删除；只有可靠删除事件或成功完成的全量清单可移除它。启动、恢复和每 30 分钟的完整检查继续保留。

无变化完整对账不得反复写入每行 `seen_generation` 或任务代次。本次扫描临时保存看到的表示键，只有完整清单和代次检查通过才处理缺失表示；不持久保存逐行扫描标记。中断后保持未就绪，重启重新核对清单并复用已确认有效的指纹。允许有界的全局检查点/状态写入，未变化的表示及任务应零写入。

### 4.2 原始版和当前编辑版

每项表示包含图库上下文、资产 local identifier、表示种类、资源/修订信息、原表示尺寸、指纹版本和状态。原始版表示编辑前图像，当前版表示用户在 Photos 中实际看到的最新编辑结果；不把当前版当作原图。

未编辑资产在能确认两种表示等价时共用一份指纹。编辑后保留有效原始指纹，生成当前版；撤销编辑时合并冗余表示。若无法可靠区分哪部分改变，重新读取受影响表示，不能凭尺寸未变复用。每个匹配结果记录具体命中哪个表示。

Photos 删除资产后移除当前候选；原始版或编辑版变化后旧表示立即失效，晚到的异步结果通过资产修订与图库代次检查被丢弃。历史成功指纹单独保留，不因当前索引清理而被删除。

### 4.3 一致性与等待

SQLite 是可恢复的指纹事实源和候选查询来源，不再维护第二份全量内存向量视图。资产更新和就绪发布使用代次，只有同一 SQLite 快照中的清单、表示、任务全部完成，且 PhotoKit 确认当前上下文/代次的令牌才能用于新的判定。发布仅传递令牌与计数，不加载整库向量。崩溃、部分写入和索引损坏后从已提交数据恢复，不能清空用户同步历史。

全局发布代次与单项任务发行代次分开：更新一个资产不重写无关任务。任务完成须核对持久任务身份、发行代次、表示修订、尺寸、等价关系、指纹版本、上下文及墓碑；已替换/撤销任务的晚结果不能复活旧表示。无关变化不单凭全局代次前进而废弃仍有效的任务结果。

首次完成后也不盲目信任旧代次：已经观察到新增或内容变化，就暂停新提交，补齐后恢复。读取未知的现存受支持资产不能被悄悄排除；单张长期不可读可能持续阻止新导入，UI 要展示原因与重试进度。确认不属于高级照片范围的资产按确定性类型规则排除并计数。索引重试继续处理其他资产，不因一个失败停止所有建设工作。

沿用 `PhotosCandidateSnapshot` 的有效性与提交检查模式，增加索引代次和本地候选修订；数据库事务内校验本地依赖与跳过证据。不得持数据库锁等待 Photos、下载或模型。每次异步等待后重新核对暂停、来源状态、文件 stamp、图库上下文和索引代次。

公开 PhotoKit 查询与提交不是跨进程事务；其他应用恰好在最后检查后导入的竞态无法彻底消除。本版保证处理已观察到的变化和重新校验，不宣称跨应用全局恰好一次判重。自身成功导入通过本地记录立即参与下一次比较，不等待 Photos 通知才生效。

## 5. 图像读取、iCloud 与资源预算

通过公开 PhotoKit 请求明确版本的图像表示；只有最终、满足版本与质量要求的结果才能生成正式指纹。降质预览、取消、错误或空结果均不能标记就绪。原表示尺寸必须来自对应资源的可信信息，不能用缩略图尺寸代替。

允许网络访问使 iCloud-only 图像按需获取，不更改 Photos 的存储设置，不要求用户永久保留所有原片。目标请求尺寸不等于网络传输字节上限，Photos 的缓存保留由系统决定；UI 和文档应说明初次索引可能下载数据且受网络影响。应用不在自己的数据目录持久保存原片或预览副本，仅保留指纹及必要信息。

图片读取/解码、iCloud 请求、推理都有固定的并发和在途内存上限；推理初始采用串行、批次 1，避免推理数量随图库增大。暂停停止新任务，已返回结果可安全落库，取消与超时不能绕过仍占用的实际资源槽位。网络或单资产失败使用有界退避，不忙循环；恢复时只重做未完成或失效项。

Photos 初始化和增量更新与来源准备共用受控资源预算，不能让十万张初始索引产生十万个同时存在的任务或解码对象。UI 只消费节流后的聚合进度。

## 6. 存储、迁移与模块边界

沿用现有 SQLite 与串行写入路径，事务化升级 schema v3，并同步核对代码迁移和 `Schema.sql`。新增的持久信息分为图库/索引代次、资产表示及指纹、可恢复索引任务、来源/历史指纹和判定证据；具体表名由实施计划确定，不建立第二套成功历史。

- `Photos/`：资产清单、变化通知和指定表示读取，不承担判重策略。
- 指纹组件：统一预处理、Core ML 生命周期和版本检查；模型产物随 App 分发。
- 检索组件：增删改与候选检索，支持由 SQLite 重建以及精确检索基准。
- `Matching/`：输入有效候选、分数、尺寸和版本，输出动作与原因，不直接执行 I/O。
- `Storage/`：迁移、原子发布、历史保护和证据一致性。
- `SyncEngine` / `SyncRuntime`：协调索引维护、已有扫描/重试与串行提交。
- `AppModel` / 日志：显示索引进度与问题，提供有界诊断信息。

模型或预处理版本不一致时禁止混用向量/阈值，重新构建对应指纹；旧已提交结果和成功历史不得因此重新导入。仅修改阈值时更新 policyVersion，保留相同 fingerprintVersion 的指纹与索引数据，不重新下载或推理全库；旧策略的决定不能直接复用。向量索引格式更新只重建派生结构。未知更高 schema 拒绝打开，禁止删库重置或静默降级。

## 8. 性能验收

在 M2 Pro 上记录冷启动、热运行、P50/P95/P99、峰值 RSS、持久存储和 CPU/GPU 占用。分开测图像读取/下载、预处理、推理、检索、SQLite 与总等待，不能只报模型耗时。

基准覆盖十万资产的全未编辑、一半编辑、全部编辑情形（最坏约二十万表示），以及单张/批量新增、编辑、删除、退出续建、休眠恢复和无变化的 30 分钟检查。1024 维 Float32 原始向量每十万表示约 409.6 MB，二十万约 819.2 MB；尚未包含索引、数据库页、历史、本地队列、模型或解码内存，不能用模型大小代替 App 内存。

验收必须证明：无变化对账不调用模型、不下载图片；单项变化只使有关表示重算；在途任务、解码内存和推理并发有固定上限；索引可分块恢复；UI 在索引过程中仍可暂停。复用当前精确检索实现与合成规模基线；集成后的测量明确标出输入规模和真实/合成来源，不为本次阈值选择重新启动算法选型。

集成工程目标沿用预先批准的 M2 Pro 热查询 P95 ≤250 ms、单张本地增量 P95 ≤2 秒、峰值 RSS ≤4 GiB；不将研究耗时直接当作产品承诺。固定配置的并发/内存上限必须通过产品测试，实测超标须修复或报告后再判定发行。独立准确率研究不再阻挡进入集成；十万真实资产与真实 iCloud 如未执行须列为缺口，不用合成数据替代通过。真实 iCloud 耗时、流量及缓存影响单独记录，不从本地 JPEG 数据外推。

2026-10-06 补充资源目标：常驻应用以低闲置占用为优先，分别报告 RSS、私有 physical footprint、可回收文件映射及查询后闲置/再次查询的变化。查询不得产生向量表、临时排序文件或其他持久写入；导入和变化维护的必要事务、WAL/检查点、决策日志另行测量，不能从查询零写入推导整个应用零写入。无变化对账应零表示/任务行写入，一项变化的写入量应与受影响表示数相关，不随全库数量增长。逻辑读取、进程记账读取与物理 SSD/NAND 写入必须区分。

最后的单遍原型在 100k/300k 合成向量上热查询 P95 为约 125/478 ms，查询部分 footprint 约 6 MiB；最大档仍超 250 ms。该事实支持实施 SQLite 以降低驻留内存，不构成性能验收通过。后续以实际完整产品路径重测，保留失败项，不调整阈值、删数据或放宽门槛来得到通过。

## 9. 日志与可解释证据

扩展已有轮转 JSONL（当前 10 × 10 MiB）和 SQLite 判定证据，不新增日志服务。每次新的导入/跳过决定记录：

- 来源记录 ID、文件 stamp、Photos 资产/本地候选 ID 与表示种类、时间、判定事件 ID；
- 模型/预处理/策略配置版本、用户决策 ID（acceptanceID）、实际阈值、图库与索引代次、就绪覆盖数；
- 最终动作和原因，来源与命中表示的原始尺寸；
- 全部候选来源合并后的最近 10 条诊断候选精确分数及 `score - threshold`，包含阈值以下近邻；独立保留最多 1 个决定候选，不因诊断截断丢掉覆盖证据；分数保留可往返的 Double 精度，无候选记空值及原因，不造 0 分；
- 读取、下载等待、推理、查询等分段耗时，失败阶段与系统错误详情。

导入也要记，尤其是门限附近的未命中和分辨率升级；不能仅记录成功跳过。重复扫描中的同一文件、相同 stamp、相同策略与有效证据不重复输出全套详情；策略变化、候选失效或重新判定形成新事件。批次索引日志记录触发原因、新增/更新/删除/失败/等待数量和耗时。

SQLite 保留当前决定所需的关键跳过证据与成功关系，不受 JSONL 轮转影响；普通诊断只保留有界候选数量，旧的非关键诊断随轮转淘汰，不积累所有 pair。日志不保存图片、完整 embedding 或图像 metadata 全量转储，不自动上传。日志写入故障沿用警告语义；数据库关键证据写入失败则不能提交一个无法持久化的跳过决定。

生产日志用于观察分数分布、边界样本、规则触发和版本回归，不能凭分数本身证明判对，也不自动根据线上分布改变阈值。更新阈值按第 7 节进行显式决策、固定回归和版本升级；本轮不要求恢复已停止的独立校准。只有阈值改变时不重算指纹，但必须重新判断符合条件的旧 skip；成功历史和未知提交继续受保护。
