# 界面与文案

菜单、设置和详情都消费同一运行快照；UI 不查 Photos 或数据库，也不另建任务状态机。目标是说明正在做什么、完成多少，以及用户是否需要操作。

## 六个整体状态

| 状态 | 含义 |
| --- | --- |
| 正在准备 | 启动读取状态，或视觉索引 / Live Photo 识别有可推进工作 |
| 正在同步 | 来源扫描、判重、提交，或 Live Photo 补齐/验证/清理推进 |
| 等待恢复 | 只剩自动重试、资源等待或 Photos 未确认结果 |
| 已暂停 | 用户暂停；已交给系统的操作继续收尾 |
| 需要处理 | 授权/存储等全局阻断、无来源且无历史任务，或只剩需要用户操作的事项 |
| 同步完成 | 无待处理、重试、验证或未知结果 |

优先级：全局阻断 → 暂停 → unknown 写入 → 同步 → 准备 → 局部需处理 → 自动等待 → 完成。局部来源离线不盖住健康任务；具体原因另列。到期且准入允许的 queued 与 working 都算活动，不能只在 worker 占用期间显示任务。

## 任务与进度

- 固定顺序：视觉索引、Live Photo。每任务只有**一行小字（名称 + 数量 + info）及一条 5 pt 纯色进度条**；已知/未知总量等宽，无渐变。未知用活动短段，不编百分比；等待/暂停停止动画、保留数量及入口身份。
- 视觉“正在建立视觉索引”，按图库资产张数；Live Photo“正在配对 Live Photo”，按核对项数。已知总量显示 `X / Y 张（项）`，未知显示 `已分析 X 张` / `已处理 X 项`；补齐/验证无可靠总量用不确定进度。
- Live Photo 普通排除/资源超限跳过计已处理，失败不计；已处理不是已补齐数量。正常完成/跳过后任务退出，**没有感叹号、警告或专用 hover**。
- 下载原件、保存到 Photos 是内部步骤，不再拆成用户任务。来源导入使用独立的“已处理 / 已发现”与分段条，不与两种图库分析合成百分比。

## Hover

任务浮层只含**标题 + 一句正文**，不加第三行、小节或滚动。真实错误可替换为一句可行动摘要；系统原文只进详细诊断/日志。

| 场景 | 标题 | 正文 |
| --- | --- | --- |
| 视觉分析 | 视觉索引 | 分析照片内容，帮助避免重复导入。 |
| 配对识别 | Live Photo 配对 | 识别照片与视频的配对关系，找到另一半后自动补齐。 |
| 补齐 | Live Photo 配对 | 正在补齐包含动态画面和声音的 Live Photo。 |
| 临时读取失败 | Live Photo 等待恢复 | 部分原文件暂时无法读取，稍后自动重试。 |
| 暂停 | 已暂停 | 已完成的结果会保留。 |
| 在途收尾 | 正在结束当前操作 | 已提交给“照片”的操作会继续收尾，之后暂停。 |
| 未确认保存 | 等待“照片”确认 | 保存结果尚未确认，新的保存已暂停。 |
| 解码超限 | 需要提高内存上限 | N 张照片超出图像处理内存上限。 |

hover 与浮层共享移入区域；支持点击固定、键盘及 Escape，更新数字/等待状态不销毁入口。实际字符串集中在 [SyncStatusPresentation](../Sources/PhotoSyncApp/SyncStatusPresentation.swift)。

## 来源、设置与详情

来源主行保留路径，次行区分“来源目录不可用，等待恢复”“部分子目录不可用”和文件问题数；根失联时只投影根诊断，底层文件问题仍保留。目录问题不计入 N 项文件问题。详情可滚动、复制完整路径/系统链，按目录、读取、提交分组；不是把任务 hover 扩成长报告。

设置中的“图像处理内存峰值上限”说明用途为解码/视觉判重，默认 2 GiB，可选 512 MiB、1/2/4/8 GiB；模型、图库和系统缓存额外占内存。来源列表限高滚动；菜单动作区固定。macOS 13 用 AppModel 持有的原生设置窗口，14+ 用 SettingsLink。
