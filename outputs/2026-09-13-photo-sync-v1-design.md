# macOS 照片单向同步程序：第一版设计

日期：2026-09-13
状态：已获用户确认，进入实施计划编写；尚未开始实现。本文整合已确认的产品规则、技术接入约束与验收要求。

## 1. 目标和边界

原生 macOS 菜单栏常驻应用，Swift + SwiftUI，最低 macOS 14；本地 SQLite 保存配置、元数据、同步记录和恢复信息。独立安装，未来采用 DMG 分发，不走 Mac App Store。

从多个文件系统目录递归导入位图照片和视频到 Photos。排除 RAW；不转码、不配对 Live Photo、不处理 XMP 等旁车编辑、不创建相簿和文件夹映射。不能导入的格式记录原因。

源目录严格只读：不移动、不重命名、不修改内容或属性、不创建标记或缓存文件、不删除。Photos 允许合理读取；写入只创建新资产，不修改、覆盖、删除已有资产。应用只保存自己的数据库和日志，不建立原片暂存缓存。Photos 自身为导入和图库管理产生的存储不属于应用缓存。

第一版不计算内容哈希，不保证内容一致性，也不检测所有编辑。允许读取拍摄时间、拍摄设备、尺寸、视频时长等媒体元数据。后续再处理复杂 GUI、精确判重、内容变更、双向删除、更多来源及闲时扫描。

## 2. 结构

单个应用进程，内部模块分离。退出应用停止同步，下次启动恢复；关闭菜单不影响运行。

- 界面与应用控制：原生菜单栏、配置、进度、启动与暂停指令。
- 同步协调：扫描调度、判重调用、四状态推进、重试和中断核对。
- 目录读取：递归枚举、文件属性和媒体元数据；所有目录同一逻辑。
- 判重：纯规则比较，返回不同或疑似重复以及依据。
- Photos 接入：读取候选、提交新增、核对结果；隔离具体系统接口。
- 本地存储：配置、状态、历史成功关系、判断依据和扫描统计。

不建设插件系统、独立后台服务、通用双向同步框架。未来窗口复用同步协调接口；新来源增加读取适配；判重算法可按版本重新处理跳过项。新增写入能力必须另行设计。

## 3. 来源与扫描

每个来源保存稳定 ID、路径和启用状态。允许多个来源；重复目录和可确认的父子重叠配置拒绝并解释。第一版不跟随符号链接，跳过隐藏项和目录包；不尝试自动挂载、保存网络凭据或判断磁盘类型。

移除来源只停用扫描，保留文件历史；重新添加相同来源可复用记录。路径是配置及定位线索，不宣称跨移动、重命名或挂载替换具有内容身份保证。文件名改变按不同照片处理；不基于哈希追踪移动。

启动后自动扫描；登录自启动独立开关，默认关闭，仅启用后注册。默认每 30 分钟触发一次；扫描不重叠、不积压补跑。提供立即扫描、暂停、继续；暂停停止启动新工作，已提交操作仍接收结果并记账。继续立即扫描。休眠唤醒只补一轮，不补跑所有错过的周期。

每轮重新递归枚举，数据库用于避免重复处理。已处理且大小、修改时间未变的文件不重复解析媒体元数据。未变仅表示属性未变，不表示内容一致。中断后允许重新枚举，不持久化系统枚举器游标。

新文件先读取必要元数据并判定，完成后才建立文件记录。拍摄时间或设备字段确实不存在属于正常缺失；文件读取失败、解析错误不能伪装成字段缺失。扫描错误保存到批次/日志，后续重扫重新发现。

对已处理文件观察到大小或修改时间变化，记录为已跳过（源属性变化），保留上次成功导入信息。待导入文件提交前再次检查属性；明显变化时先跳过，避免元数据对应旧版本。此检查不是文件快照保证，也不防止所有外部并发编辑。

## 4. 判重规则 v1

以原始文件名（含扩展名，不含目录）为入口；第一版采用字符串精确相等，不做大小写折叠、扩展名归一或模糊匹配。

1. 已成功导入的源记录优先：不重新导入，即使 Photos 后来删除对应资产。
2. 文件名不同：不同照片，不用其他元数据推翻。
3. 文件名相同：若双方拍摄时间可可靠比较，精确到秒不同，则不同；若双方设备信息完整且明确不同，则不同。任一明确冲突足以排除此候选。
4. 文件名相同且无明确冲突：疑似重复，跳过。字段一方或双方缺失不会构成不同证据。
5. 同名候选可能多条：只有所有候选都明确排除时才可导入；任何一个疑似候选都导致跳过。

时间保留原始值、精度和时区是否已知；已知时区换算为统一时间基准后截取到秒，不设容差。时区或秒级精度不足时比较结果为不确定，不推测本地时区。

设备比较采用可取得的制造商和型号，去除空白、大小写等纯表示差异，不推断设备个体身份；同型号不代表同一台相机。只在信息足够完整时以设备冲突排除候选。

尺寸、时长、大小留作记录和未来判断，不作为本版新增的排除规则。

判重同时覆盖 Photos 已有资产及本地待导入、导入中、成功导入历史，防止跨目录和同轮重复。不能将一个没有成功目标的已跳过记录当作“已导入”证据。导入串行提交，成功后立即更新候选索引。历史候选保留原文件名及元数据，避免目标删除后相同内容以其他来源再次出现时丢失依据；不同文件名仍受本版限制。

Photos 读取失败或候选索引不完整时暂停导入，不把查询错误当作空图库。不能取得设备或时间时按缺失处理，因此可能保守漏导。这符合第一版宁可暂缓、不冒进重复的目标。

## 5. 四状态与恢复

| 状态 | 含义 |
| --- | --- |
| 待导入 | 元数据和初次判定完成，等待提交 |
| 导入中 | 已记录导入意图，可能已提交，结果未确认 |
| 已导入 | 目标已确认成功，本地保留成功历史 |
| 已跳过 | 当前不处理，通过原因区分重复、源变化、不支持等 |

正常路径：发现并读取元数据 → 待导入 → 导入中 → 已导入；判定跳过则直接写已跳过。

重试次数、下一次重试时间、最近错误、本次尝试标识和候选目标标识为字段，不增加状态。来源离线、扫描失败也是来源/批次信息，不是文件状态。

在提交 Photos 前持久化导入意图。能够取得目标 placeholder 标识时尽早记录，但 placeholder 不是成功证明。[A2]Photos 成功回调后事务性更新已导入及成功关联；数据库写入失败停止后续提交，保留可核对信息。

Photos 与本地 SQLite 无共同事务，不能承诺跨崩溃严格 exactly-once：

- 核对到本次目标资产：补记成功。
- 确认查询正常、目标上下文相同、之前操作已经结束且有证据确认没有导入：回到待导入并重试。
- 查询失败、标识丢失、请求可能仍在执行或证据不足：保留导入中，延后核对；不盲目提交第二次。
- 已确认成功的历史资产后来消失：仍不重导。单次 fetch 未命中不能证明此前未成功或用户没有删除。

单张结果不确定时，不阻塞其他无关联文件；相同判重候选继续保持保守。下一版可以增加人工处理，本版不增加强制重导入口。

## 6. 慢读、失效与资源控制

所有来源统一执行读取，不建立本地媒体缓存。目录枚举、元数据读取和系统导入均离开主线程。Photos 导入并发为 1；目录读取使用固定小并发，来源之间公平轮转，不无限建立线程或任务。

来源读取失败时保存已有进度，首次通知，自动重试间隔建议 5、15、30、60 秒，之后每分钟一次；恢复成功即继续。单文件失败记录后继续其他文件；扫描不完整不推断删除。错误状态改变才通知，避免每分钟重复提示。

超时表示应用停止等待，不代表底层系统 I/O 被取消。每个阻塞读取保留实际工作占用，不因为超时启动无限替代工作；晚到结果按扫描批次及暂停状态处理。单进程不能保证任意不可中断 I/O 均可被强制终止；遇到不可恢复阻塞显示错误和重启提示。验收必须验证慢读时界面可响应，以及固定并发范围内其他来源能推进。

外部文件持续写入、库切换、授权撤回、空间不足等需要保留具体错误。图库上下文不确定时停止新增并核实，不混用旧库资产标识。

## 7. Photos 技术接入

首选公开 PhotoKit 查询和基于源文件 URL 的资产创建。采用 PHAssetCreationRequest.addResource(with:fileURL:options:) 时显式设置 shouldMoveFile=false；禁止移动源文件、禁止直接写 Photos.sqlite。[A1]不把照片解码成图像后重编码导入，以保留原文件和元数据。

第一版目标是 Mac 上设置的“系统照片图库”，通过 PHPhotoLibrary.shared() 访问，不提供任意图库文件选择。这里 shared 是程序内共用的图库接口实例，不是 iCloud 共享照片图库或共享相簿，也不表示向其他人分享照片。仅在 Photos 中打开另一个图库不会自动改变系统照片图库。iCloud 上传由 Photos 自身管理。[A8]应用的“已导入”仅代表写入 Photos 成功，不代表已上传 iCloud。

公开接口可取得的资源原始文件名、资产创建时间等用于候选索引；不假定设备型号必然是 PHAsset 的直接字段，不为全库判重自动下载全部 iCloud 原片。无法取得的字段按缺失处理。没有可靠时区来源的拍摄时间不用于排除重复。

历史调研中的 Photos 内部数据库读取不是稳定接口承诺。第一版核心流程不依赖内部数据库和最近删除列表；避免重新导入主要依靠自己的长期成功记录。内部数据库适配可作为后续精确判重的独立读取扩展。已有授权不等于必须依赖该路径。

应用申请 Photos 的 readWrite 访问并提供用途说明；用户的对话授权不能替代系统权限授予。不具备完整查询权限时暂停导入，不把不可见内容当作不存在。登录项通过 SMAppService.mainApp 注册/取消并读取真实系统状态，注册失败时显示错误而不虚报已启用。[A5]

采用普通非 App Sandbox 的独立应用作为第一版分发基线，不因 DMG 分发假定可绕过 Photos 隐私权限。源只读由读取接口、文件打开方式和测试约束落实。发布阶段再进行 Developer ID 签名与公证验收。

具体系统 API 的字段可用性、图库切换识别与中断恢复，需要实现前的最小技术验证；无法得到不存在的证据时采用上述保守恢复，不宣称确定失败。

## 8. 原生界面和全局图标

尽量采用 Apple 原生 SwiftUI/AppKit 控件、系统字体、标准菜单项、Toggle、ProgressView、目录选择器和系统符号。第一版不建设自绘仪表盘或内置日志阅读器。较长的来源配置可使用小型原生设置窗口。

图标必须独立表达全局状态，不依赖打开菜单、不只用颜色。无来源时显示未配置；有来源时，确定性优先级：需处理错误 > 用户暂停 > 等待目录恢复 > 运行中 > 本轮已完成。等待恢复图标不会被其他来源仍在运行掩盖；菜单同时显示这些来源的进度。

| 图标语义 | 触发条件 | 菜单文案 |
| --- | --- | --- |
| 警示 | 权限、数据库、图库或需处理的导入错误 | 错误摘要；正在处理其他来源时同时展示进度 |
| 循环箭头 | 无更高优先级状态，且有扫描、读取、导入或核对工作在推进 | 正在扫描/导入；同时显示不可用来源数 |
| 暂停 | 用户已暂停且无正在完成的提交 | 已暂停 |
| 等待符号 | 存在不可用目录或等待恢复任务，即使其他来源仍在运行 | 等待目录恢复／等待重试 |
| 对勾 | 本轮扫描及导入已结束，无未解决错误或待恢复工作 | 本轮已完成；下次扫描时间 |
| 普通符号 | 尚未配置来源 | 请添加来源目录 |

已跳过项不阻止本轮完成，但在摘要单独计数。图标通过形状、工具提示及辅助功能文本表达状态；完成不代表没有跳过，更不代表云端完成。

菜单内容：全局状态、当前来源/阶段、扫描数量、导入完成及待处理数量、跳过/错误数量、下次扫描时间、立即扫描、暂停/继续、设置、在 Finder 中打开日志目录、退出。没有内置查看日志功能。

扫描未结束时不展示虚构总百分比。导入阶段可以展示已知队列的数量进度，但不把系统没有提供的进度包装成字节百分比。

## 9. 本地数据和日志

SQLite 使用版本化迁移和事务。四类逻辑数据，具体表数由实现决定，不另起通用仓储框架。

- 来源：稳定 ID、路径、启用、最近扫描与错误。
- 文件：来源 ID＋相对路径唯一，文件属性、元数据、状态、原因、目标标识、重试字段；保留成功时的文件快照和关联，当前跳过不覆盖成功历史。
- 匹配：源记录、一个或多个候选、候选元数据、判定依据、规则版本和时间。
- 批次及日志：扫描开始/结束、完成与否、计数、读取错误、导入结果和恢复行为。

配置、数据库放在应用的 Application Support 目录；日志放在应用日志目录，提供 Finder 打开入口。日志滚动保存，建议最多 10 个 10 MB 文件；跳过依据与成功历史不参与日志清理。日志不记录原片内容或凭据。

## 10. 验收

必须覆盖以下有行为意义的测试：

1. 文件名不同不判重复；同名时间秒级冲突或设备明确冲突允许导入；缺失、时区不确定、全部相符则跳过。多候选任一个未排除即跳过。
2. 多目录出现同名候选不重复提交；导入成功后目标删除，历史记录仍阻止重导。
3. 元数据读取失败不建立文件记录，后续扫描能重新发现；字段缺失与读取失败区分。
4. 源大小或修改时间变化跳过；不把属性相同当内容一致承诺。
5. 四状态正确恢复：提交前失败、提交后回调前退出、成功后本地落库失败、明确未导入、安全重试及不确定时不重试。
6. 目录失效恢复、单文件错误、极慢/阻塞读取、晚到结果和有限并发：可返回的慢读/失败必须自动恢复并允许其他来源推进；不可中断读取占满固定槽位时允许受控降级和重启提示，不承诺其他来源无限推进。两种情况菜单都必须保持响应。
7. 30 分钟不重叠、启动扫描、暂停继续、自启动开关、退出重启、休眠后不积压。
8. 原生控件、各全局图标及优先级、跳过数量、日志 Finder 入口、通知不刷屏。
9. 权限撤回、图库切换、空间不足和数据库写入失败，不产生静默重复或错误完成状态。
10. 在隔离目录和测试图库验收源无写入、Photos 无覆盖/删除、应用无媒体缓存；真实用户图库写入需要明确的测试授权。

完成标准：以上行为通过相应单元测试、集成测试和 macOS 手工验收；实际 Photos 结果与模拟结果分开报告。设计阶段不对用户图库执行导入测试。

## 11. 扩展边界

下一版可基于保存的候选和规则版本重判跳过项；增加内容哈希、源修订、编辑覆盖、删除确认流程、新来源、复杂窗口或新调度器。数据库保留成功历史和迁移能力，但第一版不实现这些功能。

## 12. 技术依据与验证状态

本次阅读 Apple 官方文档核实接口语义，未构建应用、未读取用户原片、未执行 Photos 导入。以下地址为文档出处，API 均需以 macOS 14 部署目标复核可用性。

- [A1] `https://developer.apple.com/documentation/photos/phassetresourcecreationoptions/shouldmovefile`：false 时复制到 Photos；true 会移走源文件。本版强制 false。
- [A2] `https://developer.apple.com/documentation/photos/phobjectplaceholder`：placeholder 与创建对象具有相同 localIdentifier，可在完成后 fetch；未提供与应用数据库的联合事务。
- [A3] `https://developer.apple.com/documentation/photos/phassetresource/originalfilename`：导入/创建时的资源原始文件名；使用 macOS 14 可用 API，不直接依赖较新系统的重命名属性。
- [A4] `https://developer.apple.com/documentation/photos/phphotolibrary`：授权、查询/变更、变更观察和共享图库入口；不把文档列出的最新 API 全部视为 macOS 14 可用。
- [A5] `https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp`：对应主应用登录启动项，macOS 13 起可用。
- [A6] `https://developer.apple.com/documentation/photos/phasset`：公开资产元数据范围；没有直接暴露完整设备型号，本版允许此字段缺失。
- [A7] `https://developer.apple.com/documentation/imageio/exif-dictionary-keys`：源图像 EXIF 拍摄元数据；视频由 AVFoundation 可取得的元数据读取，不臆造缺失字段。

实现计划必须将三类技术验证放在正式导入之前：原 URL 创建和权限、placeholder/崩溃恢复、慢读的有限并发及界面响应。系统无法给出足够证据的场景按本设计保持不确定，不静默放宽规则。
